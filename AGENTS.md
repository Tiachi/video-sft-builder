# Project rules

- This standalone repository is `Tiachi/video-sft-builder`, public, with stable branch `main`. Task branches use `codex/<description>`.
- Read `docs/decisions.md` and `configs/project.example.json` before changing the design. Runtime configuration with null values is incomplete, not permission to guess.
- v0.2 user-facing entry is the terminal workbench: docs/terminal_quickstart.md and docs/terminal_ui_and_api_design_2026-10-21.md. Private API keys are explicitly allowed in the external user settings JSON; never copy them into versioned files, frozen run configs, logs, SQLite or reports. Each new UI build uses user prefix plus local creation time (YYYYMMDD_HHMM), with all generated artifacts/state inside that directory. Original local MP4 stays read-only at its source. Interface recipe presets are visible engineering starting values, not silently confirmed production parameters.
- Provider capability checks and explicit role routing are mandatory. DeepSeek's current profile is text/image only; no implicit video fallback. vLLM compatibility requires the served model/capacity/media contract to match, not just an OpenAI-compatible endpoint. Preserve legacy v1 JSON entrypoints and use one shared coordinator lock across UI/CLI for v2 builds.
- Current scope: Linux execution, MP4-only visual input, LLaVA three-level captions, General and Long candidate synthesis, CoT is a future standalone downstream pipeline over published QA plus video; QA release uses cot=null and must not require CoT. One combined visual QA audit. No A4 or A10. Quality failure/uncertainty goes to reject without repair, rewatch, or regeneration.
- Candidate plan: General at most 2 fit-first plus 3 task-heap-balanced candidates and Long at most 1 fit-first plus 2 task-heap-balanced candidates per eligible original video. Each branch commits fit results before its balance phase; unfilled fit slots do not transfer to balance. A pre-QA semantic abstention may advance to another task/allowed form within bounded attempts; emitted or quality-rejected QA never gets refilled. Retain every final quality-passed candidate. No final per-video caps or quota-based discarding. A null final-cap field explicitly means no cap, while unset resource values remain incomplete.
- User ratios are global targets by accepted record count: zh/en=3/7, oe/mcq=7/3, MCQ option counts 3/4/6=1/7/2. General/Long mixture is unspecified. Use ratios for generation planning and reporting only; do not discard quality-passed records, claim exact small-batch ratios, or restore rejected records to satisfy quotas.
- Store only reviewed code, configuration templates, tiny synthetic test fixtures and durable documentation in Git. No datasets, media, archives, model weights, full logs, caches, credentials, real environment files or signed URLs.
- Explicit private-relay exception (2026-10-22): the owner authorized sending one selected build plus its original MP4 through the PRIVATE `Tiachi/video-sft-builder-relay` repository's Release attachments for diagnosis. Never commit payloads to this public code repository, and never expose credentials/signed URLs. Server relay helpers must verify the exact private destination and set the server checkout's origin push URL to disabled while preserving anonymous fetch. This does not authorize public dataset publication or changing the developer checkout's push settings.
- Original media is immutable. Derived artifacts live outside the checkout. Record detailed audit/lineage outside the final training JSON; keep its 12 top-level fields.
- No silent truncation: plan and preflight full L1/L2 coverage before paid caption calls; merge only sub-minimum final tails into their predecessor, never cut them off or lower FPS. Validate persisted bundle coverage before C_GATE. Completion must independently check required outputs/branch terminal states, not just absence of pending events. Incomplete runs need visible stop location, coverage gaps, status/report/export flags and nonzero exits. Preserve raw responses. Only caption uncertain_details string-array duplicates may be losslessly normalized with provenance; all other duplicate JSON keys stay invalid. Across code fingerprints use the explicit new-build caption-only recovery with exact request matching and historical accounting; never edit old fingerprints or automatically rebill a mismatched paid unit.
- Preserve unrelated work. Stage exact paths. No auto-stash, reset, clean or force-push. When using Git synchronization, require a clean receiving checkout and fast-forward-only updates; verify the intended commit SHA.
- User decision 2026-10-22: direct SSH server inspection, edits, reviewed file transfer and execution are authorized within the task; GitHub is a maintained code backup, not a mandatory delivery hop or prerequisite. Keep complex work in reviewed versioned scripts, validate changes, preserve provenance, and maintain GitHub after coherent changes. Never ask for long pasted heredocs or strict mode in the user's long-lived shell. The server's disabled public push URL remains; the agent can maintain the backup from the local checkout.
- Server downloads default to no personal Clash/proxy, including Hugging Face, datasets, model weights, packages and Git traffic. Only an explicit user request for that download/task authorizes personal-proxy use; past GitHub troubleshooting is not permanent authorization. No automatic fallback or proxy speed tests. Use operation-scoped proxy routing and remove/restore it afterwards; inspect persistent Git proxy/environment routing before downloads. Do not change unrelated approved network settings.
- CoT enrichment publishes a new version, preserves the source QA questions/answers/options, and never overwrites or invalidates the QA release on CoT failure. Method and supervision remain pending.
- Distinguish documented, proposed, implemented, locally verified and server runtime verified. v0.1 pipeline is implemented with synthetic offline verification; real API/media/student and Linux server runs are not verified. See docs/implementation_v1_2026-10-21.md and docs/runtime_runbook.md. Runtime settings with nulls remain incomplete; synthetic demo settings are not production defaults.
- Q2: the first round produces automatically audited candidates only; human review is not scheduled. Keep human-readable batch reports, but mark human review as not performed and human error-rate/accuracy estimates unknown. This choice does not authorize expansion or claim human-verified quality. Student/format/media/split release checks remain separate.
- Q3: Long has no minimum original-video duration or arbitrary minimum evidence-span threshold. Eligibility requires the enabled task's genuinely necessary multi-segment evidence, not multiple redundant citations. The disabled minimum-duration flag makes its null seconds intentional, not a missing setting. Report actual durations and evidence spans; shorter originals can qualify, and long originals can fail evidence eligibility. Capacity/student checks still apply.
- Q4: event_timeline and hierarchical_summary are OE-only; cross_segment_qa allows OE/MCQ. Intersect task, slot and template form permissions before API dispatch. In balance, task is selected first and forms are chosen only from its allowed set; in fit, preassigned forms constrain the compatible task whitelist. Global 7:3 remains a soft target, not a reason to dispatch a forbidden form.
- Q5: the user said to skip the cross-branch/same-request OE-vs-MCQ representative policy for now. Do not add that proposed semantic deduplication/representative-selection stage or treat either suggested option as approved. Existing explicit duplicate-cleaning requirements remain; skipping this question does not disable all deduplication.
- L2 scope correction: its text summary is cumulative, but its visual input is only the current non-overlapping block (e.g. 0-30, 30-60, 60-90 seconds). Retain previous L2 text + new L1 descriptions; do not resend the whole 0-t video prefix. Original upstream L2 is text-only; adding current-block visual input is this project's extension. L1/L2 each traverse the source once visually at equal FPS; both stages together still present frames twice. Reuse the final cumulative text summary as L3, then run the separate full-video sparse C_GATE.
- Q6 applies to fixed sampling density of each L2 block, not a growing visual prefix; capacity/budget overflow is blocked without automatic FPS reduction or truncation of the required current block. Preserve partial captions; no downstream QA from an incomplete bundle. Count blocked separately from quality reject (pending in aggregate conservation). C_GATE/A7 keep separate profiles. Numeric runtime sampling values remain unconfigured; 30 seconds/1 FPS is the current explanatory example.
- Q7: the first version reserves no validation/heldout videos; eligible inputs are training candidates only and still undergo all quality gates. Preserve original-video/clip/duplicate-group lineage, but perform no QA-level or group-level train/validation split. Null validation_fraction is intentional while holdout is disabled. Do not claim independent validation or benchmark decontamination from this policy; future evaluation exclusions are not decided.
