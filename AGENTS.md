# Project rules

- This standalone repository is `Tiachi/video-sft-builder`, private, with stable branch `main`. Task branches use `codex/<description>`.
- Read `docs/decisions.md` and `configs/project.example.json` before changing the design. Runtime configuration with null values is incomplete, not permission to guess.
- Current scope: Linux execution, MP4-only visual input, LLaVA three-level captions, General and Long candidate synthesis, CoT is a future standalone downstream pipeline over published QA plus video; QA release uses cot=null and must not require CoT. One combined visual QA audit. No A4 or A10. Quality failure/uncertainty goes to reject without repair, rewatch, or regeneration.
- Candidate plan: General at most 2 fit-first plus 3 task-heap-balanced candidates and Long 3 balanced candidates per eligible original video. A pre-QA semantic abstention may advance to another task/allowed form within bounded attempts; emitted or quality-rejected QA never gets refilled. Retain every final quality-passed candidate. No final per-video caps or quota-based discarding. A null final-cap field explicitly means no cap, while unset resource values remain incomplete.
- User ratios are global targets by accepted record count: zh/en=3/7, oe/mcq=7/3, MCQ option counts 3/4/6=1/7/2. General/Long mixture is unspecified. Use ratios for generation planning and reporting only; do not discard quality-passed records, claim exact small-batch ratios, or restore rejected records to satisfy quotas.
- Store only reviewed code, configuration templates, tiny synthetic test fixtures and durable documentation in Git. No datasets, media, archives, model weights, full logs, caches, credentials, real environment files or signed URLs.
- Original media is immutable. Derived artifacts live outside the checkout. Record detailed audit/lineage outside the final training JSON; keep its 12 top-level fields.
- Preserve unrelated work. Stage exact paths. No auto-stash, reset, clean or force-push. Require a clean main checkout and fast-forward-only updates; verify GitHub and local commit SHA.
- Complex server operations must be repository scripts, reviewed and tested locally, committed and synchronized through GitHub first. Never ask for long pasted heredocs or strict mode in the user's long-lived shell.
- CoT enrichment publishes a new version, preserves the source QA questions/answers/options, and never overwrites or invalidates the QA release on CoT failure. Method and supervision remain pending.
- Distinguish documented, proposed, implemented, locally verified and server runtime verified. Current data-producing pipeline is not implemented.
