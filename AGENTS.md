# Project rules

- This standalone repository is `Tiachi/video-sft-builder`, private, with stable branch `main`. Task branches use `codex/<description>`.
- Read `docs/decisions.md` and `configs/project.example.json` before changing the design. Runtime configuration with null values is incomplete, not permission to guess.
- Current scope: Linux execution, MP4-only visual input, LLaVA three-level captions, General and Long candidate synthesis, CoT is a future standalone downstream pipeline over published QA plus video; QA release uses cot=null and must not require CoT. One combined visual QA audit. No A4 or A10. Quality failure/uncertainty goes to reject without repair, rewatch, or regeneration.
- Candidate plan: General at most 2 fit-first plus 3 task-heap-balanced candidates and Long at most 1 fit-first plus 2 task-heap-balanced candidates per eligible original video. Each branch commits fit results before its balance phase; unfilled fit slots do not transfer to balance. A pre-QA semantic abstention may advance to another task/allowed form within bounded attempts; emitted or quality-rejected QA never gets refilled. Retain every final quality-passed candidate. No final per-video caps or quota-based discarding. A null final-cap field explicitly means no cap, while unset resource values remain incomplete.
- User ratios are global targets by accepted record count: zh/en=3/7, oe/mcq=7/3, MCQ option counts 3/4/6=1/7/2. General/Long mixture is unspecified. Use ratios for generation planning and reporting only; do not discard quality-passed records, claim exact small-batch ratios, or restore rejected records to satisfy quotas.
- Store only reviewed code, configuration templates, tiny synthetic test fixtures and durable documentation in Git. No datasets, media, archives, model weights, full logs, caches, credentials, real environment files or signed URLs.
- Original media is immutable. Derived artifacts live outside the checkout. Record detailed audit/lineage outside the final training JSON; keep its 12 top-level fields.
- Preserve unrelated work. Stage exact paths. No auto-stash, reset, clean or force-push. Require a clean main checkout and fast-forward-only updates; verify GitHub and local commit SHA.
- Complex server operations must be repository scripts, reviewed and tested locally, committed and synchronized through GitHub first. Never ask for long pasted heredocs or strict mode in the user's long-lived shell.
- CoT enrichment publishes a new version, preserves the source QA questions/answers/options, and never overwrites or invalidates the QA release on CoT failure. Method and supervision remain pending.
- Distinguish documented, proposed, implemented, locally verified and server runtime verified. Current data-producing pipeline is not implemented.
- Q2: the first round produces automatically audited candidates only; human review is not scheduled. Keep human-readable batch reports, but mark human review as not performed and human error-rate/accuracy estimates unknown. This choice does not authorize expansion or claim human-verified quality. Student/format/media/split release checks remain separate.
- Q3: Long has no minimum original-video duration or arbitrary minimum evidence-span threshold. Eligibility requires the enabled task's genuinely necessary multi-segment evidence, not multiple redundant citations. The disabled minimum-duration flag makes its null seconds intentional, not a missing setting. Report actual durations and evidence spans; shorter originals can qualify, and long originals can fail evidence eligibility. Capacity/student checks still apply.
- Q4: event_timeline and hierarchical_summary are OE-only; cross_segment_qa allows OE/MCQ. Intersect task, slot and template form permissions before API dispatch. In balance, task is selected first and forms are chosen only from its allowed set; in fit, preassigned forms constrain the compatible task whitelist. Global 7:3 remains a soft target, not a reason to dispatch a forbidden form.
- Q5: the user said to skip the cross-branch/same-request OE-vs-MCQ representative policy for now. Do not add that proposed semantic deduplication/representative-selection stage or treat either suggested option as approved. Existing explicit duplicate-cleaning requirements remain; skipping this question does not disable all deduplication.
- Q6: L2 uses a fixed configured frame-sampling density over every full cumulative range; fps itself remains unset. Capacity/budget overflow is blocked, never adaptive FPS reduction, frame-cap resampling or tail-only input. Preserve partial captions; no downstream QA from an incomplete bundle. Count blocked separately from quality reject (pending in aggregate conservation). This does not change C_GATE sparse sampling or A7's separate API profile.
