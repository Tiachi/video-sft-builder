# 本阶段任务均衡、模板轮转与候选选择

日期：2026-10-20。状态：**调度设计与配置/模板已落库；生产调度器尚未实现，未调用模型。** 依据与任务边界见 [分类表](phase_one_task_taxonomy_2026-10-20.md)。

## 1. 先指定任务，再生成问题

只让模型“尽量多样地出题”无法提供数量保证。参考 [LLaVA-Video §3.3](https://arxiv.org/html/2410.02713v1) 的按任务定义、few-shot 与不可构造时返回 None 的方法，并参考 [VideoChat2 数据说明](https://github.com/OpenGVLab/Ask-Anything/blob/main/video_chat2/DATA.md) 的多任务来源组织；配额、证据适配和通过池选择是本项目自建部分。

每个通过 caption 门禁的视频按下面顺序处理：

1. **已有证据索引：** 从 L1/L2/L3 和它们的时间/实体引用提取候选事实。优先在 caption 生成响应中输出结构化事实并保留原文；兼容原脚本时可本地整理或并入 A3/A5 的同一次响应。不增加独立视觉补标/API。结构化事实不是新真值。
2. **适配集合：** 程序检查是否有 task 所需的事件数、状态对、唯一实体、跨段窗口等；无法程序判定的语义条件交给生成器返回 `abstain` 并由 A7 严查。不能用空的“有因果证据”布尔值硬路由。
3. **分配：** 从适配且启用的任务中，优先选择当前缺口较大的 task，再分配语言、题型、选项数与模板。A3/A5 必须接受指定任务，不允许改成更容易的任务充数；不适配就返回空候选/原因。
4. **生成：** 输入 task 定义、对应示例/模板、事实与绝对时间索引。回答只能使用证据。一个逻辑调用可以批量产生多个预分配候选。
5. **门禁：** 本地检查先拒绝格式错误/重复等；通过后每 QA 至多一次 A7。通过池仍不是最终发布集。
6. **选择：** 在通过池中满足 Long 每原视频最多1条、同源/近重复组约束及全局边际目标；不足就报告缺口。可以将后续未处理视频分配给缺口任务，不重跑已拒绝样本。

如果适配集合为空，该视频记 `no_supported_task`，不启动 A3/A5。该状态是路由跳过，不是 L3 幻觉失败。Long 不合格仍可走 General；L3 门禁失败则两分支都停止。

## 2. 配额语义与建议策略

| 维度 | 目标/状态 | 执行方式 |
|---|---|---|
| 中文/英文 | 用户已确认3:7 | 最终样本条数，全局边际 |
| OE/MCQ | 用户已确认7:3 | 同上 |
| MCQ 3/4/6选一 | 用户已确认1:7:2 | 只以最终 MCQ 为分母 |
| General/Long | 两者开启，比例未定 | 报实际数量，不私填1:1 |
| task | 建议权重见注册表 | 各分支内的软目标；仅对适配视频分配 |
| 来源、时长、模板 | 防集中度指标，阈值待试产 | 先报告，再校准上限；不凭空生成来源平衡 |

候选调度使用加权缺口 `max(0, target_count - planned_count)`，保留已发出但未完成的预约量，避免并发重复抢同一缺口。接受结果到达后更新供给估计；未通过不自动触发重生成。目标总量未知时，可使用加权轮转并持续报告累计偏差。

最终选择默认采用**可解释的分层规则**：质量硬门禁先通过；然后按任务/全局边际缺口、证据覆盖充分性、模板/来源集中度选择；同分用固定 seed 和 sample_id 排序。任何审核硬失败不能被加权分数抵消。模型自报的“99分”不作为校准质量分；当前 `quality.score` 可为 null。

若所有候选已知，可以用带容量约束的整数选择优化替换贪心；这是备选实现，不是本轮增加求解器依赖的理由。必须披露缺口，不能宣称贪心保证所有边际同时最优。小样本、来源和任务适配限制可能使目标不可达。不要在每个 task×分支×语言小格子内要求完全相同比例。

## 3. Long：3 条候选、最终最多1条

仅对 Long 适配的视频预先规划3个候选槽位。优先覆盖不同的适配任务/证据组合；仅有一种适配任务时，可使用不同问题但必须确实不同，不能复制同题。模型可因证据不足返回少于3条，原始返回数与请求槽位分别统计，不重生成补足。

所有实际产生的候选都按模块4检查；如果本地先拒绝，A7调用数少于候选数。在通过池中最终选最多1条；通过但未选中的候选写 `selection_excluded`，不写质量 reject。若实际产生3条，P条通过，则：

```text
quality_reject = 3 - P
selected = min(P, 1)
passed_not_selected = max(P - 1, 0)
```

模型 abstain 导致只产2条时，将3替换成2，并另报 `requested_slots=3, generated=2, abstained_slots=1`。三个候选不是固定三次 A5 调用；建议一次 A5 请求返回三条分任务候选。一次调用若整体格式不可用，本轮拒绝/记录技术状态，不靠循环继续付费。

## 4. General 数量先评估

`general_candidates_per_video` 仍为 null，不把候选3条或最终1条的 Long 规则错误推广到 General。建议在获批的首轮范围内，将视频按来源/时长/适配复杂度分层，比较 **1、3、5 个预先分配候选槽位** 的成本与增益；这些只是离线试验档位，预算与样本量待定。

选型看：每视频新增的非重复合格问题、覆盖的 task 数、长尾任务供给、每有效样本成本、人审错误率和学生证据可见率。选收益已趋平的较小档位；不要只按原始生成数越多越好。该试验在开始前固定分组与调用预算，不能给审核失败的视频追加候选。

## 5. 模板库：本轮交付192个中英文种子模板

实际文件：[question_templates.json](../configs/question_templates.json)。12个启用任务 × 每任务8种表达/关注方式 × 中英双语 = **192个种子模板**。每条兼容 OE 与 MCQ，共384种“模板×题型”组合；384不是独立措辞数，模板数也不是语义多样性的验证结果。

每条含 `template_id/task/language/stem/required_slots/supported_question_types/answer_styles`。占位槽位必须由已存在的 caption 事实填充；`time_ref` 由程序将绝对时间锚渲染为自然措辞。不能由模板暗示正确选项、添加未观察对象或把“为什么”自动包装成因果。

特别地，`evidence_a/evidence_b/segment_a/segment_b` 在**问题文本中只能填不泄露结论的片段指代线索**，例如“开始装盘的片段”，不能填“开始用红盘、结束用蓝盘”后再问盘子如何变化。完整事实放外部证据账本供生成/审核，不直接抄进问题。`relation_query`只填待求关系；如果问法本身给出答案或无需视频即可解出，A7拒绝。这是模板实现时必须防的标签泄露风险。

轮转键为 task×language×question_type；优先少用模板，同视频避免重复，固定 seed 保证可复现。候选生成的**同一请求**完成槽位填充与小幅改写，保存模板种子和最终问法，之后才进入 A7。审核后不再改题。MCQ 选项由结构化事实构造，要求同一语义维度、互不等价、唯一正确、干扰项不靠语法/长度泄露；3/4/6选项数由程序分配。选项位置用固定随机 seed 打乱并同步更新字母答案，不混淆成多选。

答案使用多种自然表达：短事实、完整句、对比句、按序概述等，但要服从问题需求与语言，不强行把所有答案写成长段解释。没有证据的细节不能为“丰富表达”补进答案。MCQ 最终 assistant 仍只输出单字母，解释不混入答案字段。

模板防重复采用本地规范化文本、n-gram/MinHash 或字符相似度，不接 A10。报告最常用模板占比、有效模板数、标准化问法重复率、答案长度/开头分布、选项字母分布、各任务证据覆盖及人审结论。本地相似度只能筛表面重复，不能保证语义去重；这项限制必须保留在报告中。

## 6. 不新增独立 API 的接口约束

参考实现提示见 [task_generation.md](../prompts/task_generation.md) 与 [quality_audit.md](../prompts/quality_audit.md)。它们是**提示合同草案**，尚非经过真实模型调优的可用生产 prompt。

- A3/A5 接收明确的 task 与配方，不让模型任意选择全部类别。
- 不足返回 `abstain`，禁止附带猜测答案。
- 不新增模板改写 API；改写在生成请求中一次完成。
- A7 同一次请求同时判断支持性、答案、选项唯一性、task 与语言/时序要求；一次综合判断不等于保证每项都能可靠判断。
- caption 门禁是 QA 生成前独立的 C_GATE，不是恢复 A4，也不计为逐题 A7。
