# CoT 后续独立链路：以已发布视频 QA 为输入

日期：2026-10-21。状态：按用户决定更新的架构与接口；**本轮只拆分设计，没有实现或运行CoT生成程序，具体方法仍待调研。**

## 1. 两条链路与发布边界

```text
QA主链路（当前四模块）
MP4 → 视频预清理 → 三级caption与L3门禁
    → General/Long QA候选 → 本地检查/A7 → 选择 → QA数据发布

CoT独立链路（之后搭建、单独启动）
已发布QA数据 + 对应原视频 + 可选既有证据
    → CoT构造 → CoT独立核验 → 通过 / CoT reject
    → 单独发布带CoT的数据版本
```

QA主链路不等待CoT、不调用CoT生成/核验API。CoT失败不使已发布QA自动失效，不回流修改问题、答案或选项。QA本身的质量、媒体路径、划分、报告与学生训练兼容验收仍然保留；取消的仅是“缺少CoT就不能发布QA”的前置条件。

## 2. 独立链路输入

| 输入 | 必须性 | 内容 |
|---|---|---|
| 已发布的QA数据版本 | 必需 | general/long的最终入选记录，包含id、问题、固定答案/选项、task、语言、视频引用；不从未审核候选或reject补数据 |
| 对应原MP4 | 必需 | 通过媒体索引解析；沿用原片绝对时间，不仅拿问答文字生成解释 |
| caption/事实/视图索引 | 可选辅助 | 复用已保存产物以定位证据，不能把caption当作视频真值；缺失时不得编造 |
| CoT配置、模型API与预算 | 必需，未来提供 | 独立配置/运行ID；模型角色、方法、调用次数、监督格式和阈值待选型 |

关联键使用 **`QA发布版本 + sample_id`**；原id在派生版本中保留，版本与血缘在外部清单记录，避免不同版本同id混淆。Long只对主链路最终保留的那一条QA补CoT，不重新启用另外两条候选。

## 3. 工作与输出

1. 校验QA输入版本、记录身份、原片可定位以及语言/任务/答案一致性。
2. 基于QA与真实视频构造可检查的CoT。是否向生成教师显示标准答案、采用何种结构、是否监督仍待方法研究；本次不冻结四阶段方案。
3. 单独核验视觉事实、时间、推理与固定答案的一致性。不能为了得到既定答案而编造依据；若不支持/矛盾，拒绝CoT产物。
4. 通过者发布到新的CoT数据版本，原QA版本只读。若发现疑似QA本身错误，生成独立问题报告供后续处理，不静默修答案或覆盖已发布文件。
5. 如果CoT进入训练目标，重新组装学生序列并计算输出/监督/总token、检查长度与可见证据；不得继承QA版的旧输出token计数。

建议外部目录：

```text
cot_derived_root/cot_run_id/
  input_manifest.json                 # QA版本、样本id、媒体映射、配置/代码版本
  candidates.jsonl                    # CoT候选
  checks.jsonl / reject.jsonl          # CoT审核与拒绝，独立于QA reject
  lineage.jsonl / api_calls.jsonl      # 血缘、调用与费用，无凭据
  reports/report.md                   # 输入/通过/拒绝、分布偏差、成本、人审
  release/<cot_version>/{general,long}.jsonl
```

详细证据、模型/提示版本、调用与统计全部外置。CoT筛选可能改变task/语言/题型/分支比例，报告应比较输入QA版本与CoT版本的分布，不能宣称原QA比例自动继承。

## 4. 12字段如何兼容

| 版本 | `cot` | `conversations`与token |
|---|---|---|
| 当前QA版本 | **`null`**，表示此版本没有CoT标注；不是失败状态 | 问题及最终答案；按QA训练目标验收token |
| 后续CoT版本 | 方法确定、构造并核验通过后的object，子结构待定 | 保留原问题/答案/选项；若监督CoT，学生适配器另组训练目标并重新计token |

两版本仍保留既定12个顶层字段；不因拆分链路删掉`cot`，也不新增顶层`cot_status`或额外metadata。CoT处理状态和来源版本放外部记录。QA版的`cot=null`是正式允许值；CoT版本发布则必须有已核验的CoT，不允许用null冒充。

## 5. API与审核次数的关系

主链路A1/A2/C_GATE/A3/A5/A7不变，A7只审核QA。未来独立链路需要CoT生成与核验的模型能力，可复用同一服务，但使用独立配置、预算、调用记录与报告；实际请求次数在方法选型后确定，本轮不启动。

“每QA最多一次A7”约束仍适用于QA主链路；后续新建的CoT核验针对新产物，不是QA审核失败后的补看/修复。不能借独立链路名义重新生成已拒绝的QA。
