# 纯视频SFT四模块方案：整体评估、漏洞与逐项决策

日期：2026-10-21。评估基线：`a7133cc71e39e18dfb8cea1eb3af3c5fe69bc1c7`。目标是面向用户指定GLM的纯视觉视频SFT数据构造，而非复现某篇论文的全部生产系统。

**结论：有条件继续。四模块主线可行；现有合同足以组织实现，但不足以证明产物高质量或可直接训练。优先补齐审核视图、人审校准、成本边界和跨分支最终验收，再扩大生产。**

本文是评估与建议，未修改生产默认值、运行媒体处理、调用模型或启动训练。用户问题按第12节逐个讨论；待答项不能自动视为同意。

## 0. 评估问题、证据状态与优先结论

评估问题：在“MP4＋模型API、三级caption、General适配2＋均衡3、Long适配1＋均衡2、一次A7、失败不返工”的约束下，能否以可控成本产出真实、可学习、足够多样且可追溯的QA，并最终帮助GLM视频SFT？

| 证据状态 | 当前实际情况 |
|---|---|
| Documented / 已文档化 | 四模块、12字段、来源与时间、两分支、caption前置门禁、一次A7、外置统计、独立CoT合同 |
| Implemented / 已实现 | 示例配置、模板/prompt草案、离线设计检查与Git同步辅助；不等于数据生产器 |
| Locally Verified / 本地验证 | 前版设计/算术检查通过；本轮只读核对这些合同及新评估文档 |
| Runtime Verified / 目标环境验证 | 没有真实MP4/API/GLM预处理或训练结果 |
| Proposed / 本文建议 | 审核视图衔接、校准与门禁、状态提交细则、试产矩阵；未逐项冻结 |

最关键的四项：

1. **正确答案与可学习样本不同。** 教师看见、学生没采到的事件，会形成缺证据的训练目标。现有“学生视图覆盖”条款需要可执行接口，不能只靠时间窗重合。
2. **一次A7是预算约束，不是准确率保证。** 需要用分层人审估计错误接受，不能把模型通过率当真实正确率。
3. **累计L2可能是主要成本。** 必须在开始昂贵caption前预估全片预算；“时间范围全覆盖”不代表“每个短事件都可见”。
4. **最终通过的边界尚需收紧。** A7通过、跨分支去重完成、学生验收通过、正式发布，是不同状态。计数与“合格全保留”必须使用同一终态定义。

没有发现必须推翻四模块的证据；也没有证据支持现在宣称“无幻觉”“严格task均衡”或“训练收益已验证”。

## 1. 最终成果应怎样验收

### 1.1 最小可发布的工程成果

不是论文发表要求，而是项目首版最低交付：只读媒体清单、可恢复四模块程序、配置冻结、完整中间证据、General/Long统一12字段、真实质量报告、可运行的GLM数据适配与发布门禁。所有实际输入视图与输出标签可追溯。

没有目标processor时可以交付**模型无关候选版本**；不能把它称为已通过GLM训练兼容验收。12字段结构本身可以不变，状态仍为候选/待验收，正式release不混入pending记录。

### 1.2 较强成果

在未用于反复改prompt的组级留出视频上，人审错误率达到事先约定的标准，并报告置信区间、拒绝率、每视频/每单位费用的新增非重复合格QA、各task/语言/题型偏差、学生证据可见性和资源长尾。

### 1.3 扩展成果

固定学生版本、训练token预算和评测协议，证明新数据相对强基线有稳定收益，且没有依赖评测视频泄漏或只记住选项/问法。CoT仍单独研究，不作为当前QA版发布前提。

### 1.4 不能代替成果的指标

JSON能解析、prompt很完整、模板数量多、A7通过率高、堆的task条数接近、同一视频产满8题，都不能单独证明数据正确、多样或有效。

## 2. 正确性与均衡的理论边界

### 2.1 权威对象和必要条件

权威事实来自原MP4的实际可见画面；caption、事实账本、教师答案与审核解释均是模型输出，不是独立GT。实际训练输入由冻结的学生采样、缩放、processor与chat template决定。

对候选q，发布至少需要：

```text
release(q) = 原片事实成立
          AND 学生实际输入足以回答
          AND 任务/题型/语言/时间与格式成立
          AND 去重与组级split成立
          AND 数据与媒体关联、token和发布完整性成立
```

这是目标合同，不是目前已有判定器能精确证明的布尔表达式。A7、人审与自动检查是有误差的测量；学生证据充分是必要条件，仍不足以保证学生训练后获得能力。

### 2.2 三个反例

- **稀疏采样反例：** 两次采样之间发生并结束的短动作，在原片存在，但检查/训练视图都可能没有。原片时间窗覆盖并不能补回缺帧信息。
- **错误一致反例：** L1误认工具，L2延续该称谓，L3与QA措辞一致，审核又受候选答案锚定；多阶段一致并不提供独立事实证据。QA使用保留的L1/L2，故不能假定L3已逐条核实它们。
- **均衡不可达反例：** General全部5条都通过、fit的2条总是动作题，则动作至少40%，无法达到九类均匀的11.1%。Long若fit总是同一类、balance通过率低，也可能因fit在合格集占比超过1/3而无法均匀。

设合格数据中fit占比α、fit任务分布f、balance分布g，目标分布p满足`p=αf+(1−α)g`。每类`α*f_t≤p_t`是精确可达的必要条件，还不是充分条件；视频证据供给、同题去重、阶段额度与预算还有限制。维持用户确认的2＋3、1＋2与软均衡，不借评估擅改配额。

### 2.3 两道门禁不能按独立误差相乘估算

即使以H表示某QA事实错误，错误漏入的概率也取决于`P(A7通过 | H, 前置门禁已通过)`。不能未经实测将两个审核的错误率当作独立事件相乘；它们可能共享教师、表述和采样盲区。

算法算术正确、运行状态正确、任务标签真实、训练有效是四个独立验收层。现有离线测试主要覆盖第一层及配置不变量。

### 3.1 方法重合与创新边界

分层caption、按任务出题、模型审核、比例调度、模板轮转均已有方法基础，本项目当前价值主要是组合与可靠交付。没有开展足以支持“新算法/顶会创新”的查新，本次也不以发表为目标。

若以后形成可量化的证据可见性或成本控制方法，仍需另做查新和强基线对比；自有数据、换用GLM或加小根堆本身不能直接算研究创新。

## 4. 实际价值、简单基线与适用范围

优点在于范围收敛：纯视觉、推迟计数/OCR/精确边界、保存L1/L2、时间可追溯、质量失败不返工、CoT独立，均有助于先形成可审查的QA版本。两阶段调度也比完全自由出题更可控。

真正要优化的是**预算内新增的真实、非重复、学生能回答的训练监督**，而不只是QA数量或类别条数。视频源贫乏时，均衡调度不能创造不存在的关系证据。

试产应保留强简单基线：同一caption底座上的固定轮转task；与当前小根堆2＋3/1＋2比较。小任务集合直接扫描字典也可实现相同选择，堆并非决定收益的创新点。

同一原片重复训练多个QA，会增加视觉token暴露。条数7:3不等于监督token7:3；MCQ答案短、Long OE长，这属于指标解释而非更改用户比例。后续混合训练需单独报告token与原视频贡献，不能在本版生成后删合格题来配平。

## 5. 端到端成本、资源和停止边界

设视频v有n个L1请求、m个L2前缀请求，QA生成调用数g，实际进入A7的题数a：

```text
C(v) = 媒体探测/采样/传输/派生存储成本
     + Σ C_L1 + Σ C_L2 + C_C_GATE
     + Σ C_QA_generation + Σ C_A7
     + 学生预处理与人审成本

g_常规 = (1个General-fit + 3个General-balance)
       + (1个Long-fit + 2个Long-balance) = 7
a ≤ 已生成QA ≤ 8
```

两分支全适配、无弃答、8题都进入A7时，视觉caption之外还有`1+7+8=16`个逻辑请求。按现有**建议**尝试预算，生成阶段上界为`1+12+1+5=19`次，连同C_GATE及最多8次A7为28次；L1/L2另外计算。上界不包括未冻结的网络策略，不是自动运行授权。

固定L2采样密度f、步长w、长度D=Kw时，视觉帧呈现约`fwK(K+1)/2`。这是重复输入量估算，不能直接换算成账单：API可能按像素、视频时长或token计费，缓存与上传也不同。全范围固定帧数可以降低增长，但牺牲短事件覆盖，不能称等效。

应测`总费用 / 新增非重复合格QA`，不能用成功调用均价掩盖caption失败沉没成本。若希望新增机制有价值，需要在相同质量约束下，其新增合格QA相对成本优于简单基线；没有教师价格、真实通过率时不能给出可靠每条单价。

本项目不是推理加速论文，Amdahl只用作工程边界：若调度开销占总时长s，即使调度无限快，整体加速也不超过`1/(1−s)`；优先实测累计视觉与A7，不夸大堆的性能意义。

资源报告含各角色帧/像素/输入输出、上传流量、缓存身份、派生空间、p50/p95/p99时延、挂起请求、并发配额与每视频预算。外部模型服务能耗不可见时标unknown；不编造能耗或显存数字。原片时长/分辨率在跑caption前就可用于有界预算预估。

| V13 P1 已知残余风险 | 全累计L2重复输入与Long上下文极限 | 长片前缀费超预算、过晚才blocked | 先用元数据估算n/m/帧像素，再测少量长度分层 | 预检全片资源包；限额内全范围采样；超额blocked，见D02 | 不静默裁尾/截caption，不擅自改累计语义 |

| V15 P0 实现门禁 | PTS合同正确，但seek、VFR、rotation与重复帧尚无真实验证 | 原片绝对时间正确格式却指向错误画面 | 非零start/VFR/旋转/短片/末尾样例回放 | 用真实解码PTS；存缩放/旋转映射；容量与异常单独归因 | 时间/图像映射失败样本不发布；不自动重编码原片 |
| V16 P0 实现门禁 | 12字段不是实际训练reader合同 | 字段被忽略、MCQ字母错、labels未遮mask、序列被截断 | 小型真实processor读入/渲染/labels/token smoke检查 | 统一内部schema、可追溯渲染/洗HTML、学生专用适配 | 无processor实测则不标GLM兼容；不拼造token |

| V18 P1 接口缺口 | 历史权重字段、旧批量prompt、简化合成统计仍留库；新合同检查不等于完整schema | 实现者误用旧权重，abstain尝试被当最终槽位 | 比较主配置/调度配置/注册表/新prompt/统计定义 | 唯一有效版本入口；区分尝试abstain与最终槽位未产；报告按终态聚合 | 新旧合同矛盾未消除，不开始正式批量 |

## 7. 七项核心决策卡与四模块落点

### D01：审核与学生视图衔接（提问Q1，待答）

- **建议：** A7优先使用GLM实际训练的帧与分辨率，输入时间索引也来自该视图；原片仍为事实来源，caption用于候选而非GT。另一个可行选项是同一次A7包含教师与学生两套视图并分别判定，增加输入费用与锚定风险。
- **依据/状态：** 学生配置为空，发布合同已要求覆盖；这是project-observed＋derived，不是已经跑通的处理器能力。
- **迁移边界：** 若学生每epoch随机采样，一份冻结视图不能代表所有可能输入。首版可考虑固定采样，或另外验证采样分布下的证据可见性；不擅自用答案相关oracle选帧替代实际训练/推理采样。
- **备选：** 先做通用候选，等processor可得再验收；此时不承诺训练就绪。
- **改变建议的证据：** 两套视图在相同输入预算下显著减少人审误判、且学生支持判定稳定，才优先考虑双视图。
- **落点：** 模块1记录原片映射，模块2记录教师视图，模块4冻结学生视图/审核接口；全部详细记录外置。

### D02：全片预算预检，而不是尾部失败后补救（待确认资源取舍）

- **建议：** 模块1元数据后，先估L1/L2/C_GATE/生成/A7最坏资源包；预算不足的整片记blocked。累计范围和失败不返工保持现决定。
- **依据/状态：** 第5节成本推导＋caption合同，derived/proposed；当前没有真实单价/吞吐。
- **备选/边界：** 全范围固定帧数更省，但可能漏事件；更密集可见性更好但费用增加。不能把“累计范围完整”偷偷改成“最后一段”。
- **改变条件：** 实测长度分层的新增合格QA/费用与人审误差；若目标长片始终不达标，报告当前方法的适用上限，另议方案。
- **落点：** 模块1预检，模块2逐请求预算扣减，模块4实耗报告。

### D03：用人审校准一次A7，而不是增加逐题审核轮数（待确认质量目标）

- **建议：** 首轮分层盲审auto-pass与reject，区分严重事实错、缺学生证据、选项非唯一、时间错、task虚标。抽样覆盖fit/balance、两分支、语言、来源和时长；同视频多题按组处理。难例与随机样本分开统计。
- **依据/状态：** 项目原有人审要求、判断偏差文献以及统计推导；proposed，未有人审结果。换一个教师可以替换审核后端，不自动等于增加第二次审核，也不能替代校准。
- **备选/边界：** 全人工更贵；只审模型低分题会引入选择偏差。对已经发现错误的样本只reject，不修答案后回填。
- **可证伪门禁：** 正式扩大前约定可接受的错误率与成本；未达标就停扩量/缩适用范围。不能把“模型自报100分”作为证据。
- **统计例子：** 若独立随机抽n条、零错误，单侧95%二项上界为`1−0.05^(1/n)`。假设业务选择错误率上限2%，至少149条零错才满足这一简化条件；2%仅举例，未替用户设定目标。视频相关性与分层加权会改变有效样本量，不能把同视频多题硬当独立149条。
- **落点：** 模块4人审队列、分层估计、发布结论；不增加正式逐QA模型调用。

### D04：task与题型适配先有白名单，再追全局配方（待确认首版兼容矩阵）

- **建议：** 评估时间线/层级总结是否首版以OE为主或仅OE，跨段QA仍可MCQ；General按证据支持题型。保持语言3:7、OE/MCQ7:3、MCQ3/4/6为1:7:2的**全局软目标**。
- **依据/状态：** 注册表每类都允许两题型；form弃答已有，但缺兼容边界，project-observed/proposed。
- **备选/边界：** 所有task允许两类最灵活，但多消耗不适配调用；兼容矩阵更稳，可能限制局部多样性。不能为了补6选1硬写5个不可靠干扰项。
- **改变条件：** 按task×形式审唯一性、文本捷径与费用；若长摘要MCQ可靠且有独立价值，再扩该格子。
- **落点：** 模块3任务注册与允许形式；模块4题型/干扰项专项检查。

### D05：同视频两分支共享问题历史，去重发生在最终通过之前（待确认保留粒度）

- **建议：** General/Long使用统一video级已产问题/答案/必要事实索引；不同task名称、语言、OE/MCQ形式不自动意味着不同监督。相同窗口上的不同所求可以保留，不能按证据重复直接删题。
- **依据/状态：** 两分支同片最多8条，当前prompt已有历史字段但作用域不明确；project-observed/proposed。
- **备选/边界：** 仅文本归一化/MinHash便宜但漏语义改写；将少量同视频历史放入既有A7可辅助判定，但仍不能保证语义去重。没有新增A10或embedding API。
- **改变条件：** 人审显示重复主要是表面文本即可稳定解决，则首版可用更简单规则；否则不能声称完成语义去重。
- **落点：** 模块3共享历史与模板；模块4跨分支质量去重/代表规则，完整决定外置。最终质量合格全保留，不借去重按配额裁题。

### D06：统一终态和事件状态机（实现建议，不要求用户审批每个状态名）

- **建议：** reserved→generated_pending→local/A7_pass_pending_final→final_pass或reject/blocked；passed堆项仅统计定义一致的最终合格记录，pending覆盖尚待去重/学生验收的候选。模型调用失败单独归因，遵守既定次数/不返工策略。
- **依据/状态：** 当前堆定义与发布合同未有生产接线，project-observed/proposed。需要在实现时补状态与幂等/回放测试。
- **备选/边界：** A7后立即计passed较快，但会错误宣称代表最终供给；如果批量验收延迟长，堆主要依据pending，这是需如实报告的统计滞后。
- **改变条件：** 所有后置验收都已完成且不可变时可提交final_pass；异常回放不得重复扣减/计数。
- **落点：** 模块3与4共用外部状态；一次A7中断不自动重发。不同新run不是幂等重试的替代名。

### D07：隔离调参集、确认集和外部benchmark媒体（待确认评测用途）

- **建议：** 模块1先定义父原片/剪辑/近重复组，再固定开发与未触碰确认集；若要汇报某benchmark成绩，应核对训练候选与其媒体/片段重合，问题文字不同不代表无泄漏。
- **依据/状态：** 项目已要求组级split，但`split_policy`为空；来源共享机制见文献表。proposed，不声称已经证明无污染。
- **备选/边界：** 只有随机QA级split最省事，却不能保护同片泄漏；按来源整体留出更强但可能改变分布。缺来源元信息时可以补媒体指纹和人工检查，但不宣称穷尽。
- **改变条件：** 若仅做内部数据质量迭代，可先固定原片组确认集；未来对外报benchmark收益再补更严格重合审计。
- **落点：** 模块1分组与评测排除，模块4验收；benchmark_refs仍只是能力参照。

## 8. 最小试产与反证实验矩阵

以下是后续实验计划，没有因为写入文档就授权运行。样本量、教师/学生、价格与预算另行冻结。

| 实验 | 固定与变化 | 核心读数 | 何种结果反驳首选方案 |
|---|---|---|---|
| E1 视图对照 | 同一QA、相同实际学生输入；对照教师丰富视图 | 人审真实正确/学生可答、漏事件分层 | 大量原片正确却学生不可答，说明现审核接口不能发布 |
| E2 门禁校准 | 冻结prompt/模型/采样，分层审通过和拒绝 | 错误接受、误拒与分层CI | 总体尚可但Long/因果等分层严重失真，不可用总体均值掩盖 |
| E3 稀疏门禁覆盖 | 静态、短事件、剪辑、多人物与长片 | 关键claim完整性、C_GATE错拒/漏判 | 长片几乎全拒或重要事实大量漏过，需缩适用范围/重议采样 |
| E4 调度消融 | 同视频池/底座/质量标准/成本边界；简单固定轮转对照当前2＋3/1＋2 | 非重复合格QA/费用、task偏差、弃答与时延 | 堆明显更贵而覆盖和产量无改进，保留简单实现作备选，不自动改用户阶段数 |
| E5 题型兼容 | 逐task测OE、3/4/6选1；不同时改其他prompt | 唯一性、人审、选项捷径、form弃答费 | 某task×形式稳定失败，收紧兼容格而非硬补比例 |
| E6 视频依赖负控 | 留出诊断集对比完整学生视图、单段/单帧、无视频/时间打乱 | 诊断准确率差、人审必要证据判断 | 时序题对缺失/打乱不敏感且人审确认可走捷径，拒绝该类构造 |
| E7 故障恢复 | 纯合成状态、模拟服务响应，不花模型费 | 请求数/额度/终态/堆是否守恒、原子发布 | 重复付费风险或双计数未控制，禁止正式扩大 |
| E8 学生预处理 | 冻结真实processor/采样/模板与少量合格QA | 解码帧、完整序列、labels、tokens、MCQ渲染 | 截断必要视觉或答案、token字段不实，禁止训练就绪发布 |
| E9 学生训练验证 | 有预算后，固定总训练token、优化器、初始化与隔离评测 | 任务分层增益、seed波动、泛化与退化 | 更多QA只改善已见模板/污染数据，不支持“训练更好” |

E6只用于单独预算的验证实验，不在正式主链路为每题加额外API；不修改原片，不把负控结果当作完整因果证明。删单段后仍可答也可能存在替代证据，需人审确认，不能全自动当作无效题。

先选长度/来源/事件密度/分辨率的交叉代表层，不只选10个好处理的视频。保存固定ID、分组、抽样seed和所有负结果；prompt调优使用开发组，最终确认组只在规则冻结后检验。重复试验以视频组配对/聚类，异步运行记录调用顺序，不将固定seed等同于并发完全可复现。

计时从视频清单入队到可发布完成，分解探测/采样/上传/模型等待/生成/审核/学生处理/人审；报告冷缓存与复用视图两种成本。扩量前先测API配额及共享存储IO，避免把大并发带来的尾延迟当作算法效果。

## 9. 逐级门禁与失败动作

| 门禁 | 通过条件 | 失败动作 |
|---|---|---|
| Gate0 合同与输入能力 | 单一生效配置；PTS/样本ID/状态正确；目标API确实支持所需有序视觉；预算可计算 | 修实现或保留候选状态，不开批量；不是重生成被拒QA |
| Gate1 最小真实闭环 | 小规模端到端、有明确图像/时间/答案支持，A7与学生接口可执行，统计守恒 | 停在相关模块；保留reject/blocked，不降门禁凑量 |
| Gate2 质量与成本 | 冻结标准下，随机分层人审达用户约定错误率/区间；单位新增合格QA费用可接受 | 不扩大；校准后仅以新版本/新轮次处理新授权输入，不偷偷复活旧reject |
| Gate3 规模与鲁棒性 | 确认集质量、长片预算、故障恢复、分布及语义重复可控 | 缩适用范围或暂停该分层；合格全保留规则不变 |
| Gate4 发布/训练收益 | processor、labels/token、媒体、split、报告及不可变发布全部验收；声称训练收益须另过E9 | 没有训练证据只能交付已验收数据，不能写收益已验证 |

质量阈值与实际资源数值待逐条讨论；不编造2%/1000条/某FPS为已确认参数。不把未来CoT方法待定作为QA版阻塞条件。

纯视觉是已经确认的要求，不重新询问是否消费音频；V19是API适配必须落实的能力门禁，实际教师输入通道不可只凭配置名字认定。

## 10. 失败后的备选组合

| 触发 | 备选与可复用资产 | 价值/风险 |
|---|---|---|
| 学生processor暂不可得 | 继续caption与模型无关候选，保留全部视图/证据，延后GLM正式release | 复用高；避免伪造兼容，后验仍可能发现不可学样本 |
| Long累计视觉过贵或核验通过太低 | General在可验证范围继续；Long保留候选/blocked，另议上限与采样 | 不擅改两分支启用决定，也不把Long标签贴给短片充量 |
| 某task/形式错误集中 | 新版本兼容矩阵收紧该格，不强补task或题型 | 保留底座、合格数据与统计，范围会缩小，需要明确记录 |
| 堆相对简单轮转无增益 | 保留阶段数与配方，考虑简单调度实现作为对照或后续替代 | 改动小；是否切换仍依据试产与用户决定 |
| 单教师一次审核未达标准 | 先校准prompt/适用范围，或替换A7后端；保持每题一次请求 | 不自动叠加多轮审核；不同模型也需人审校准 |

这些是备选设计，不是已执行变更。没有任何备选允许修复旧reject后偷偷回流。

## 11. 评分与最终判断

评分仅表明当前设计成熟度，非测量值、质量分或作者能力评价。1=证据弱/未闭环，5=已有充分实测。

| 维度 | 1–5 | 依据 |
|---|---:|---|
