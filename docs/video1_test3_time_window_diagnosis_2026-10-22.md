## 2. 根因：多窗口声明与单窗口校验不一致

生成协议允许一个 fact 使用多个 evidence_window_ids，但旧 validate_audit 要求每一条支持区间都必须包含在其中某一个窗口内：

~~~python
any(support_start >= w["start"] and support_end <= w["end"]
    for w in this_fact_windows)
~~~

例如某事实声明了 0–10、10–20、20–30 三个连续窗口，A7 返回 0–25。该区间没有离开它声明的总体证据覆盖，旧规则仍会拒绝。切片边界不能被误当成一个事实最多只能持续多久的边界。

另一方面，不能把“多个窗口联合覆盖”偷换成“只要落在最早起点和最晚终点之间”。如果声明的是 0–10 与 20–30，区间 0–30 中间存在 10–20 的无声明空隙，仍应拒绝。

修复后的条件为：

~~~text
A7 的每条支持区间 I，必须完全包含于该 fact 声明窗口的并集：
I ⊆ union(W_fact)

允许相邻/重叠窗口形成连续覆盖；
不跨空隙、不借用其他事实的窗口、不自动扩大引用、不裁剪响应、不加时间容差。
~~~

这只修正程序对既有多窗口引用的解释，原始全片边界、必要事实支持、多段必要性与全局三阶段检查继续执行。

## 3. 本次代码修改

### 3.1 本地证据区间：小函数逐段检查完整覆盖

[quality.py](../src/video_sft_builder/quality.py) 新增 covered_by_windows，按窗口起点排序，从支持区间起点推进覆盖终点；遇到未覆盖空隙立即失败，覆盖完整个区间才通过。

~~~text
cursor = 支持区间.start
按起点排序该事实的窗口：
    跳过已落在 cursor 之前的窗口
    若下一个窗口.start > cursor：拒绝
    cursor = max(cursor, 窗口.end)
    若 cursor >= 支持区间.end：通过
最后仍覆盖不完整：拒绝
~~~

零长度、反向、非有限时间都不能视为有效覆盖。保持严格边界比较，不因很小的超界就自动放过。

对真实附件的原始 A7 响应作只读离线回放，结果为：

| 原因类别 | 新本地规则回放 |
|---|---|
| 两条总结的连续跨窗支持 | 本地校验通过 |
| 时间线首事实越出自身声明范围 | 仍为 audit_support_outside_claimed_window |
| General 由模型主动拒绝 | 仍为 temporal_grounding |

回放没有调用模型、没有改写原文件、没有更新旧 SQLite、quality 或 exports。它使用的是旧模型判断，不能代替新 prompt 的真实评估。

### 3.2 A7 提示：明确每个事实的时间协议

[audit.txt](../prompts/runtime/audit.txt) 增加：

- 只用该 fact 自己声明的窗口检查支持范围。
- 相邻/重叠窗口可联合覆盖；分离窗口不能用一个大区间跨过空隙。
- 同一事实有分离证据时，可返回相同 fact_id 的多条证据。
- 不能把真实观察硬裁到引用范围，不能照抄粗窗口端点来伪装动作边界。
- 如果所需支持确实在引用范围外，temporal_grounding 不能为 pass。
- task_validity 应检查问题实际所求；问动作不能仅因出现实体就归为实体属性。
- 语言检查要覆盖重复介词、范围短语生硬拼接；剪辑形式本身不证明人物意图或回忆关系。

A7 原有一次原视频审核不变，不增加追问、补题或再次观看调用。

## 4. 同时发现并小幅处理的题干问题

### 4.1 时间范围标记被当成时间点

已有 [[TIME:window_id]] 会展开为完整时间范围。模型把两个这样的标记用“至/到”连接，得到“从一个范围到另一个范围”的笨拙表达。

本次不新增时间点字段或复杂标记：

- 整片总结/时间线优先说“整段视频”或“the entire video”。
- 真正限定某一局部时段时，仍使用一个已有窗口 TIME 标记。
- 不把首/末窗口标记拼成整片起止点。
- 原片绝对时间及禁止臆造数字时间的检查继续保留。

### 4.2 重复介词

旧渲染样式之一以“在”开头，模型也可能在 TIME 标记前写“在”，程序替换后变为“在在”。

render_time 现在只生成不带前置介词的时间范围名词短语，由模型在外层补语法。例如：

~~~text
在[[TIME:w]]中 → 在原片00:01:15至00:01:25这一段中
in [[TIME:w]] → in the 00:01:15–00:01:25 segment of the original video
~~~

实际样式仍受 seed 控制，不固定成唯一表达。绝对时间来源未变；窗口是粗范围，不是动作精确边界。

本地测试能保证该渲染器不再额外插入第二个介词，但不能保证模型自身不会写出其他病句。没有用一个语言正则去静默改写所有旧题干。

### 4.3 task 漂移、重复所求与叙事臆测

本轮被拒的 General 样例登记 entity_attribute，实际问题询问动作；两条 Long 总结的所求和证据也高度重合，改一个模板并没有创造新问题。

[运行生成 prompt](../prompts/task_scheduler/generation.system.en.txt) 因此进一步明确：

- 实际所求必须符合 task；实体属性与动作描述不能混用。
- 同一全片总结换说法/模板仍是重复所求。
- 已拒候选仍属于已经发出的题，不因此获得补题许可；证据耗尽可在未产题时弃答。
- 总结只陈述可见阶段和转换，不凭剪辑风格补出“计划、回忆、现实”等关系。

这些是对既有约束的补充，不增加语义去重模型、跨分支代表选择策略或按新规则自动删除通过数据。能否减少模型漂移仍待真实运行验证。
