## 读取范围的解释

```text
video_root/
  a.mp4          # 本层
  b.mp4          # 本层
  sub/
    c.mp4        # 子目录
```

- 仅本层：处理a、b，不处理c。
- 包含子目录：处理a、b、c。

该项用户尚未选择，配置为null。既不默认递归，也不要求用户现在确定未知目录布局。

## 配比

| 内容 | 用户给定 | 分母 |
|---|---|---|
| 中文/英文 | 3:7 | 最终通过样本总条数 |
| OE/MCQ | 7:3 | 最终通过样本总条数 |
| MCQ三/四/六选一 | 1:7:2 | 仅MCQ条数 |
| General/Long | 两者都启用；比例未给定 | 不自行填成1:1或任意比例 |

按最终条数作为登记默认解释，不推断用户要求按token或视频数配比。上述是全局边际目标，不自动要求每视频、每分支、每任务内都精确满足。

100条成品示例：中文30、英文70；OE70、MCQ30；MCQ中三选一3、四选一21、六选一6。各项同时精确为整数时，总条数至少需要是100的倍数；很小的批次仅报告接近程度与实际分布，不伪造精确性。

语言与题型可在生成前分配目标配额，生成后保留所有最终合格记录并报告偏差，不按配额裁掉合格题。不生成同题中英文副本来机械充数，不放回reject数据，不启动审核失败后的重生成补齐。若总体供给无法满足比例，报告缺口。配比只用于生成前调度与统计，不再设计通过池配额筛选器。

本轮20%的MCQ为六选一，是用户给出的明确配比，替代先前“少量六选一”的模糊表述；不擅自降为其他比例。

## 当前流程

```text
原片预清理 → L1局部视觉 → L2累计范围视觉合并 → L3
→ L3+全片稀疏视觉门禁（失败caption reject，QA数0）
→ A3通用出题 / 基于既有caption的A5长视频出题
→ 本地检查 → A7一次QA综合审核
→ 最终质量检查 → 合格全部保留 / reject / pending → QA发布验收（cot=null）

独立后续链路：已发布QA + 原视频 → CoT构造 → CoT核验 → 新CoT版本 / CoT reject
```

A4和A10移除；不把A4更名后重新引入。审核失败/不确定直接reject，无补标、补看、修答案、返工或重生成。原片只读，reject保存候选与原因，不删除MP4。完整成品仍要覆盖12字段；详细caption、证据、质量与API记录外置。

CoT改为之后搭建的独立下游链路，不进入当前四模块、不阻塞QA发布。QA记录保留12字段且cot=null；CoT版另存新版本，不覆盖QA问题/答案/选项。CoT失败不影响已发布QA，方法、子结构和监督策略尚未决定。当前已完成设计调研、配置/模板、离线设计一致性检查与Git同步辅助脚本，没有正式生成管道或服务器运行证据。

独立链路合同见[cot_standalone_pipeline_2026-10-21.md](cot_standalone_pipeline_2026-10-21.md)。
