# 三级 caption、绝对时间与两道幻觉门禁

日期：2026-10-20。状态：设计合同；原公开脚本已静态核对，本项目适配器与生产门禁尚未实现。此文覆盖旧文档中“L2仅文本”和“caption直接流入QA”的历史方案。

## 1. 原开源逻辑与本项目改造

固定来源：[LLaVA caption 脚本](https://huggingface.co/datasets/lmms-lab/LLaVA-Video-178K/blob/6d8c562dc26d70042a0d9704d1cae58c94b89098/gpt4o_caption_prompt/GPT4o_description_prompt.py)，revision `6d8c562dc26d70042a0d9704d1cae58c94b89098`。原逻辑使用局部视觉描述、文本累计汇总，并把末次汇总作为全片描述；不是可直接传任意 API/目录的完整生产框架。[既有代码审计](llava_video_videochat3_pipeline_code_search_2026-10-20.md) 保留原行为说明。

| 层级 | 当前项目输入 | 范围与输出 | API / 原代码差异 |
|---|---|---|---|
| L1 | 当前局部窗口的有序视觉帧、真实时间、必要历史 | 局部描述及支持窗口 | A1视觉；沿用骨架，重做PTS与客户端 |
| L2 | 上次累计L2文字＋本轮新增L1文字＋**本轮新增完整分块视觉** | 画面如0–30、30–60、60–90秒；输出摘要文字依次覆盖0–30、0–60、0–90秒 | A2视觉；给原文本递推加入本轮画面是项目扩展，不重送0–t画面 |
| L3 | 最后一次累计文字合并结果 | 全片caption，保存独立版本/依赖 | 默认复用末次累计L2文字，不重复生成同义总结；末次L2只看本轮新增画面，不是全片视觉复核 |
| C_GATE | L3文本 + **覆盖原片全范围的稀疏视觉视图** | pass/reject及可追溯检查记录 | 新增独立视觉审核，每视频最多一次；通过才有QA |

建议保留所有L2累计文字摘要，末次与L3通过`derived_from`引用同一结果。**这与原输出将末次摘要移出L2的容器形状不同，须登记本项目schema版本，不改写原始响应。** 不足一个分块的短片处理其实际全长；末次不足完整分块时处理剩余段，均保存累计摘要及L3引用，不重复付费生成同义总结。

这里“完整分块”表示本轮新增区间的时间覆盖，不是重送累计画面，也不表示原片每一帧或无限分辨率。例如第二次L2输入30–60秒视觉，历史0–30秒以已存L2文字承接；输出摘要仍覆盖0–60秒。局部、L2分块和检查视图分别保存真实时间、尺寸、帧数与请求ID；原生视频上传还要核服务采样与限制。详见[L2范围与成本纠正](l2_visual_scope_and_cost_correction_2026-10-21.md)。

## 2. 稀疏检查怎么做、失败后去哪

在配置允许的帧/像素/上下文预算内，检查视图按固定、与QA无关的策略覆盖全片：均匀时刻、首尾有效帧；可加入预计算的镜头代表帧但不把镜头当事件真边界。精确采样密度、预算与阈值等待 API 能力探测，不写死为已验证参数。不得在检查失败后补一轮稠密视图。

C_GATE 输出内部合同至少包含：`video_id, caption_version, view_id, decision, claims[], primary_reason, request_id`。`decision` 为 pass/reject/uncertain/error；仅 pass 放行，其他均进入 caption reject，技术错误单独归因。每个claim保留所检查的原句、可见支持或矛盾的时间引用、无法判断项。模型没有看到的细节不能认作“不存在”。

默认采取保守标准：L3 的关键实体、动作、顺序/结果必须在本次视图下有充分支持；重大事实无法判断就拒绝。允许生成阶段不描述看不清的细节，但门禁不能通过删改 L3 修复。保存原片引用、L1/L2/L3、检查视图与响应，便于人审漏检。

```text
L3门禁失败 → 02_caption/reject.jsonl（video/caption级）
            → 该视频本轮A3/A5调用数=0、QA生成数=0
L3门禁通过 → 模块3候选 → 本地检查 → A7一次视觉综合审核
                                      → 失败进QA reject；通过进合格池
```

L3检查不逐条验证全部L1/L2细节。若A3引用L1独有细节，仍需A7原视频支持；不能用“L3已通过”替代逐题视觉证据。稀疏视图会遗漏短事件；报告应把采样覆盖与人审错误接受率列为风险，不宣称已消灭幻觉。

## 3. L2分块视觉输入的成本与容量

设全长D秒、L2分块步长w秒、固定密度f帧/秒；每个不重叠分块只看一次，不计端点重复及padding：

```text
L2视觉帧呈现数 ≈ fD
相同采样密度的L1也约为fD；两层合计约2fD
```

例如1小时、每30秒一块、1FPS，L2约120次×30帧=3,600帧呈现。旧217,800帧估算属于重送全前缀画面的误读，撤出当前方案。帧数相同仅在相同像素/编码条件下对应接近的视觉token；L1/L2文字输入与输出不同，不能承诺总费用相同。C_GATE及A7另计。

Q6固定密度与超限blocked保持，但范围修正为当前新增完整分块。单块视觉容量、递推文字上下文与全片总预算分别预检；不降密度、不截断当前块。服务端若强制降采样且不可禁用，则blocked。保存中间结果，完整bundle/C_GATE未通过前QA=0；blocked归入pending、不计质量reject。C_GATE稀疏全片检查与A7配置独立。30秒/1FPS是本轮算例，未冻结的运行数值仍保持待配置。

## 4. 原片绝对时间

所有时间统一为**原始MP4播放时间轴、从原片起点起算的秒**，不是Unix时间，不是局部窗口相对时间。保存容器start_time、stream time_base、真实PTS和映射版本；不要假设所有MP4第一帧PTS天然为0。

```text
absolute_time = normalized_original_window_start + local_time
```

前提是 local_time 已被对应解码视图实际定义。程序只做映射、格式化、上下界/顺序检查，不能从窗口0–10秒推断动作恰好0秒开始、10秒结束。时间锚类型在外部证据中区分 `sample_point / evidence_window / event_boundary / relative_anchor`；本版不产生未经专门核验的 event_boundary。

例：原片窗口120–150秒，帧在窗口内第8.4秒，原片位置为128.4秒。可以问“约02:08时画面中的…”，只有该时刻确有支持时才使用。若caption只说明120–150秒窗中有某操作，可以问“02:00–02:30这一段…”，不能改写为“该操作从02:00精确持续到02:30”。

开头/结尾使用类型化 `relative_anchor=begin/end`，渲染为“刚开始时”“进入最后阶段后”“near the end”等自然表达。只有定位的是开场/结尾阶段而非精确动作边界时允许；问题要求具体秒数时不能用 begin/end 回避。最终 OE 自然语言中的时间与外部结构化时间都要校验；不能只校验外部索引。

## 5. 失败与中间状态

格式失败、技术错误、证据不足、事实矛盾分开记录；它们都不自动触发返工。每个逻辑请求有幂等ID，已完成不可重复付费；不确定服务端是否完成时记 `unknown_execution` 待人工处理，不盲目重发。本阶段建议 C_GATE 与 A7均SDK retries=0、最多一次请求；上游生成阶段的技术重试策略在运行前单独配置，不能继承公开脚本的错误目录无限重跑循环。

所有检查与筛除写统一事件账本，具体分母、视频/QA单位和报告见 [统计与发布合同](phase_one_metrics_and_release_2026-10-20.md)。
