后续用户倾向L1/L2直接传10秒/30秒视频、2FPS，详见[型号专属像素参数与2FPS重算](qwen38_flash_native_video_2fps_cost_2026-10-21.md)。该文以API参考中的默认max_pixels=655360为主；本节8保留通用示例条件对照，并纠正原先1184×640的向下取整误算，不再作为型号默认报价。

## 2. 从1080p画面换算视觉token

按官方图像估算规则，Qwen3.8每视觉token对应32×32像素，使用预处理后的宽高并计图像标记。1920×1080在该示例的32倍数取整下约为1920×1088：

```text
每张图像token ≈ 1920 × 1088 ÷ (32 × 32) + 2
             = 2,042
```

本次假定像素预算允许这一尺寸，未另行缩小。宽高取整是模型预处理估算，不改写原MP4；PNG/JPEG文件大小不是这个token公式的分母。服务实际预处理、时间文字和封装可能有差异，最终以usage与账单为准。[官方图像与视频token估算](https://help.aliyun.com/zh/model-studio/vision)。

**不能直接把这个2,042套到API原生视频/视频列表。** 官方视频示例还有帧配对及像素预算，见第8节；不同输入形式必须分别估算。

## 3. 文字与输出用量假设：这部分不是实测

只有时长、分辨率与模型名不足以确定账单。为得到可计算金额，本次明确采用以下平均长度；它们既不是用户已定值，也不是官方“每题标准用量”。

| 角色 | 每次输入文字token假设 | 每次可见输出token假设 | 内容/解释 |
|---|---:|---:|---|
| A1-L1 | 平均6,000 | 平均300 | prompt/时间＋必要历史L2/本块L1文字；输出局部描述 |
| A2-L2 | 平均6,000 | 平均4,000 | 上一条累计L2＋3条新L1＋规则；输出累计描述 |
| C_GATE | 10,000 | 2,000 | 假设最终L3约8,000，加prompt/时间；返回关键claim/判定 |
| A3-fit | 128,000 | 1,800 | caption证据包/模板/白名单等，最多2题 |
| A3-balance | 每次128,000 | 每次900 | caption证据包＋固定task/槽位，最多1题 |
| A5-fit | 128,000 | 1,400 | Long时序证据/模板/约束，最多1题 |
| A5-balance | 每次128,000 | 每次1,400 | Long单题生成 |
| A7 | 每次2,000 | 每次1,000 | 问答/选项/task/必要事实与时间；综合判定 |

采用128K文字的原因：360条L1若各300token，已约108K，再加最终L3、必要阶段摘要、ID/时间和prompt，按128K作情景预算。这是避免把一小时caption证据包低估成几百token；**没有把全部120个累计L2版本都无上限重复拼入每次生成请求**。

L1/L2的历史长度与累计摘要实际可能远大于或小于此假设；平均L2输出4K也不代表足以保全一小时事实。若必须保留更多细节，就要增加预算或blocked，不能仅为符合估算数值删事实。2K的A7输入也需容纳256帧时间标识；实现后要实际序列化计数，而不是按表硬截断。

## 4. 调用次数

```text
A1：3,600 ÷ 10 = 360次
A2：3,600 ÷ 30 = 120次
L3复用：0次
C_GATE：1次
General：1次fit + 3次balance = 4次
Long：1次fit + 2次balance = 3次
A7：8题 × 每题1次 = 8次

合计 = 360 + 120 + 0 + 1 + 4 + 3 + 8 = 496次
其中视觉请求489次，纯文本生成请求7次。
```

L2依次看0–30、30–60、……、3570–3600秒，不重送0–t画面。L1/L2各3,600帧呈现；仅这两层共7,200帧。C_GATE/A7不是每个检查项各调用一次。

## 5. 分角色费用：1080p逐帧图片、关闭思考

计算规则：`费用 = (视觉输入token＋文字输入token)×0.8/1,000,000 + 输出token×2.7/1,000,000`。

表中token均为该角色所有请求之和；“输出”不含第7节另计的内部思考。金额展示保留多位是为了核算，**不表示估算具有对应精度**。

| 角色 | 调用次数 | 帧呈现量 | 视觉输入token | 文字输入token | 输出token | 费用约/元 |
|---|---:|---:|---:|---:|---:|---:|
| A1-L1 | 360 | 3,600 | 7,351,200 | 2,160,000 | 108,000 | **7.90056** |
| A2-L2 | 120 | 3,600 | 7,351,200 | 720,000 | 480,000 | **7.75296** |
| L3复用 | 0 | 0 | 0 | 0 | 0 | **0** |
| C_GATE | 1 | 128 | 261,376 | 10,000 | 2,000 | **0.22250** |
| A3-fit | 1 | 0 | 0 | 128,000 | 1,800 | **0.10726** |
| A3-balance | 3 | 0 | 0 | 384,000 | 2,700 | **0.31449** |
| A5-fit | 1 | 0 | 0 | 128,000 | 1,400 | **0.10618** |
| A5-balance | 2 | 0 | 0 | 256,000 | 2,800 | **0.21236** |
| A7 | 8 | 2,048 | 4,182,016 | 16,000 | 8,000 | **3.38001** |
| **合计** | **496** | **9,376** | **19,145,792** | **3,802,000** | **606,700** | **19.99632≈20.00** |

例如A2不是只有视频帧费用：

```text
视觉：120 × 30 × 2,042 = 7,351,200 token
文字：120 × 6,000 = 720,000 token
输出：120 × 4,000 = 480,000 token

费用 = (7,351,200 + 720,000) × 0.8 / 1,000,000
     + 480,000 × 2.7 / 1,000,000
     = 7.75296元
```

合计拆账：视觉输入约15.31663元，文字输入约3.04160元，可见输出约1.63809元。总输入22,947,792token，约22.95M；输出约0.607M。

## 7. 默认思考可能如何改变费用

官方[深度思考文档](https://help.aliyun.com/zh/model-studio/deep-thinking)列明Qwen3.8-Flash为混合思考模型、默认开启思考，支持显式关闭。思考token计入输出；QA训练数据`cot=null`与教师API内部是否思考是两回事。

目前没有该标注任务的真实thinking usage，不能把某个平均长度说成默认值或官方推荐值。只做敏感性计算，假设额外思考不被传回后续caption文字上下文，其他用量保持不变：

| 情景 | 额外思考token合计 | 增加费用约/元 | 全链路费用约/元 |
|---|---:|---:|---:|
| 显式关闭思考 | 0 | 0 | **20.00** |
| 仅8次A7各额外4,096token，其余关闭 | 32,768 | 0.08847 | **20.08** |
| 全部496次平均各额外4,096token | 2,031,616 | 5.48536 | **25.48** |
| 全部496次平均各额外32,768token | 16,252,928 | 43.88291 | **63.88** |

这些是**不同情景，不是20–63.88元的保证区间**，真实输出可以超出假设。只有usage已经包含thinking时，不要在completion/output费用上再加一次。关闭思考只是计算基准，没有据此覆盖用户“审核配置参考官方”的方向；实际A7推理配置仍需单独选定并验证质量。

## 8. 分辨率/输入形式会怎样改变结果

| 比较方案 | 改变的内容 | 无思考全链路约/元 | 调用次数 | 限制 |
|---|---|---:|---:|---|
| 主表：1080p逐帧图片 | 每帧约2,042token | **20.00** | 496 | 作为主估算，不保证采样充分 |
| 图片先缩至1280×720 | 相同采样，预处理约1280×704，每帧约882token；全部角色同步变化 | **11.30** | 496 | 改变有效分辨率，不能未经确认作为已实施的省钱策略 |
| 仅L1/L2改原生视频编码的条件推算 | 固定1FPS不变，按下述示例像素/配对公式；C_GATE/A7仍维持主表图片方案 | **10.31** | 496 | 不是Qwen3.8-Flash默认服务行为的实测结论，见下文 |

官方视频估算示例按`ceil(帧数/2)×预处理帧面积/1024＋2`计数，并受总像素预算约束。**因此不能一边用视频时序编码的便宜token数，一边声称保留了主表1080p独立图片输入。** [官方视频token估算](https://help.aliyun.com/zh/model-studio/vision)。

10.31元那一行的完整条件是：采用官方通用示例中“非qwen3-vl-plus”每帧像素上限`768×32×32`，且10/30帧短块不触发总像素限制，1920×1080按示例约缩至1152×640；单对帧面积为720token。初版误写1184×640；按floor取整的正确宽度是1152，此处及计算器已同步纠正。

```text
L1每次视觉 ≈ ceil(10/2) × 720 + 2 = 3,602 token
L2每次视觉 ≈ ceil(30/2) × 720 + 2 = 10,802 token

两层视觉总量 = 360×3,602 + 120×10,802 = 2,592,960 token
主表两层视觉 = 14,702,400 token
节省输入费   = (14,702,400 − 2,592,960)×0.8/1M = 9.687552元
条件总额     = 19.9963236 − 9.687552 ≈ 10.31元
```

官方文档示例含旧模型常量，不能把该示例参数直接当成Qwen3.8-Flash生产默认值。接入时应核对新模型实际支持/生效的帧与像素预算，再以usage修正。服务降采样若破坏L2固定密度则blocked；不能因上述价更低而自动切换输入形式或降低密度。本行是机制对比，不是10.31元的报价承诺。

## 9. 弃答、额外审核与超限的成本边界

### 9.1 有界弃答改派

如果采用现有General均衡最多12次、Long均衡最多5次的**工程建议**，生成请求最多19次，总调用最多508次；不是产508条QA，实际候选仍最多8条。12/5尚未冻结或在生产实现。

在主表文字/输出预算不变的条件下，相比成功路径，多9次General balance、多3次Long balance：

```text
额外文字输入 = 12 × 128,000 = 1,536,000 token
额外输出预算 = 9 × 900 + 3 × 1,400 = 12,300 token
额外费用     = 1,536,000×0.8/1M + 12,300×2.7/1M = 1.26201元
合计         ≈ 21.26元（508次，关闭思考）
若508次各额外4,096思考token：≈26.88元
```

弃答通常可更短，但这里为额外请求预留同样单题响应预算；实际文字输入/输出超过假设时仍会更贵。此数不是不附条件的最大账单。已产QA质量拒绝不补题，A7不追加第二轮。

### 9.2 不能默认每题A7看一小时原分辨率1FPS图片

该设想每题3,600张图，视觉输入就约7,351,200token，超过官方模型页列出的百万级上下文，也超过本次URL多图上限。按当前“一题一次A7”合同，应blocked；不能默默拆成很多次调用，或自动缩小/减帧后仍宣称按原要求审核。

### 9.3 长文字累计仍有费用风险

若累计L2文字持续增长，A1/A2后期请求与QA证据包都要重算。主表没有给出无限长caption的价格。额外增加10,000token输入一次，只多0.008元；如果在480个caption请求中每次都多10,000token，就累计多3.84元。费用由“每次长度×出现次数”决定，不能只看某次很便宜。
