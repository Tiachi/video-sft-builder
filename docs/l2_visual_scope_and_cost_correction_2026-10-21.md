# L2视觉范围与token用量：需求理解纠正

日期：2026-10-21。更正基线：`931d79cbeaa6110f9e0327dd0e660a872434fcb8`。状态：源码静态核对、设计与算术纠正；没有调用模型、处理媒体或验证真实账单。

**用户关于用量的理解成立：如果L2每次只看本轮新增的不重叠30秒、以1FPS取帧，其全视频视觉帧呈现总量可与同为1FPS的L1相同。此前助手把“累计摘要”误扩成“每次重送累计视频前缀”，导致当前成本估算和配置范围偏离用户意图，现予纠正。**

## 1. 累计的是文字摘要，不必累计重送画面

固定源：[LLaVA caption脚本](https://huggingface.co/datasets/lmms-lab/LLaVA-Video-178K/blob/6d8c562dc26d70042a0d9704d1cae58c94b89098/gpt4o_caption_prompt/GPT4o_description_prompt.py)，revision `6d8c562dc26d70042a0d9704d1cae58c94b89098`；[论文§3.2及图2](https://arxiv.org/html/2410.02713v1#S3.SS2)。

原始递推逻辑：L1看当前约10秒帧；每约30秒，L2把上一次L2文字与最新三个L1文字合并，输出截至当前的累计摘要。原脚本的`prompt_video_description`通过文本调用完成L2，本身不重新输入视频。末次摘要作为全片描述，是原流程中可复用的结果。

本项目加入视觉后的明确设计为：

```text
L2第1次：L1[0–30秒]文字                  ＋画面[0–30秒]   →累计摘要[0–30秒]
L2第2次：上次L2文字＋L1[30–60秒]文字     ＋画面[30–60秒]  →累计摘要[0–60秒]
L2第3次：上次L2文字＋L1[60–90秒]文字     ＋画面[60–90秒]  →累计摘要[0–90秒]
```

这里区分三个范围：本轮视觉范围、本轮新增L1文字范围、输出累计文字范围。它们不能都叫“累计范围”而不加区分。所谓L2“检查”，是同次视觉合并时结合本轮画面校正和生成，不新增一轮独立检查API。

末次不足30秒也处理完整剩余段；分段采用不重叠的时间/帧身份，端点按实际采样规则处理。L3仍可复用末次累计L2文字，随后用全片稀疏视觉做C_GATE；不能再声称末次L2本身看到了全视频画面。

## 2. 90秒、1FPS算例

假设两层都为1FPS，缩放/视觉编码配置一致，暂不计端点重复或padding：

| 阶段 | 每次画面范围 | 次数及每次帧数 | 全片视觉帧呈现量 |
|---|---|---|---:|
| L1 | 0–10、10–20、…、80–90秒 | 9次×约10帧 | 约90帧 |
| L2（纠正后） | 0–30、30–60、60–90秒 | 3次×约30帧 | 约90帧 |
| 两层合计 | 同一组画面在两个阶段分别输入 | 不是免费复用一次输入 | 约180帧呈现 |
| 旧误读的L2 | 0–30、0–60、0–90秒 | 30＋60＋90帧 | 180帧，仅用于说明误差来源，当前不采用 |

因此：**L2单层约等于L1单层，两层合计仍约为单层两倍。** 已经抽取/缓存了图像文件只减少解码和存储IO，不自动免掉另一阶段的模型输入费用；缓存计费以实际API为准。

一般地，时长D、统一采样密度f时：

```text
L1视觉帧呈现量 ≈ fD
L2视觉帧呈现量 ≈ fD
L1＋L2         ≈ 2fD
```

1小时、1FPS对应L2约3,600帧呈现；此前217,800帧只属于反复重送前缀的另一种算法，不适用于本次纠正后的方案。这里的1FPS/30秒用于回答用户的算例；实际配置尚未冻结的数值仍保留待配置，不推断其他角色也被设为1FPS。

## 3. 为什么不能把“帧量相同”写成“账单完全相同”

- 每帧像素、缩放/裁剪、图像或原生视频输入形式、视频时序编码、分组padding与服务端预处理可能不同，所以视觉token只能在相同处理条件下比较，不能仅按帧数承诺精确相等。
- L1与L2的system/prompt、历史文字、输出caption不同。L2包含递推摘要，文字上下文长度可能增加，也可能被摘要策略压缩；总输入/输出token与费用不必等于L1。
- L3后的稀疏C_GATE、QA生成与A7另计；原脚本L2仅文本，本项目增加L2视觉本来就增加一遍视觉输入。

质量门禁不变：本轮画面支持新增事实，历史摘要仍可能携带错误；L3稀疏检查不是逐帧完整证明，QA仍要一次A7。纠正成本模型不能被解释成已验证无幻觉。

## 4. Q6容量策略的修正落点

固定抽帧密度、超限blocked继续成立，但单次L2画面容量以**当前分块**计算，不按0–t全前缀计算。长片可能因总轮次费用、累计文字上下文、单块像素或后续全片检查容量而blocked，不能再仅因原片长而假定每次L2视觉帧数不断增加。

保存部分结果，未获得完整L3且未通过C_GATE前不进入QA；不降密度、不截断当前分块、不在失败后改参数重试。此修正不改变C_GATE全片稀疏视图或A7独立配置。
