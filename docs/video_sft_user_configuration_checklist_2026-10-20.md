## 1. 现在启动准备前，确实需要你提供的内容

“必须”指实际接入/试跑前需要明确；本轮只整理清单，不读取实际媒体或调用付费API。

| 编号 | 配置内容 | 你需要填什么 | 示例/说明 | 必需程度 |
|---:|---|---|---|---|
| U1 | 运行位置 | 在当前电脑还是某台服务器运行；服务器给已有主机标识/连接方式即可 | `当前Windows电脑`；或`已有连接的某Linux服务器`。不必在聊天里给密码/私钥 | 必须 |
| U2 | MP4根目录 | 运行机器上真实的绝对目录路径 | 示例：Windows的`D:\video_input`；Linux的`/data/video_input`；这些只是示例，不是已验证路径 | 必须 |
| U3 | 读取范围 | 只读目录本层，还是包括子目录；是否只用一份指定文件清单 | 建议首轮只处理明确的10个文件；没有子目录时可答`仅本层` | 运行前明确；不填默认仅本层 |
| U4 | 派生产物目录 | caption、候选、reject、缓存、最终JSONL写到哪里 | 必须是运行机器上可写、与原片/代码目录分离的数据目录；无需按问题复制原MP4 | 必须 |
| U5 | API服务商与入口 | 实际服务商/网关、base URL或完整请求地址，接口协议或对应文档 | 模型名相同不代表网关相同；请保留地址中的区域与版本路径，不凭模型名猜入口 | 必须 |
| U6 | API凭据配置方式 | 已配置的环境变量名，或让运行环境按约定变量配置凭据 | 建议约定`QWEN_API_KEY`；它是项目读取的变量名，不声称SDK会自动识别。只需说明本机/服务器已配置，不需要发密钥明文 | 必须；有现成认证方式可直接说明 |
| U7 | 本轮消耗上限 | 首轮允许的费用上限及币种；若无法实时获知费用，明确最大请求/输入规模等硬限制 | 如`首轮不超过___元，最多___次API请求`。不能承诺预算未超时必然完成全部题目 | 付费调用前必须确定停止边界 |
| U8 | 首轮处理规模 | 本轮用哪10个文件，或允许按清单顺序选最多10个；是否有指定测试视频 | 当前按前文场景建议首轮最多10个，不自动把整库都跑一遍 | 可直接答`目录里就10个，全部` |

U1/U2/U4必须属于同一运行环境，例如服务器处理时，不能把当前电脑盘符当成服务器可读路径。U5若已经提供完整请求文档，协议、鉴权头和endpoint字段可由实现者提取，不需要你重复抄写。

实际API与模型ID按用户最新回复保持待定。前文`qwen3.8-flash`用于流程演示；正式接入时提供实际网关model字符串。

### 1.1 API相关信息中，有则提供、没有不必编造的项目

| 配置 | 说明 | 没有时如何处理 |
|---|---|---|
| 部署区域/项目或工作空间ID | 仅在服务鉴权、路由或计费确实需要时填写 | 从现有endpoint/文档识别；无需为本项目专门新建 |
| 官方限流/账户限额 | RPM、TPM、并发、单次图片数/视频限制等 | 标为未知，由文档与受控接入探测确定，不把不知道填成无限制 |
| 第三方网关差异 | 非标准鉴权头、模型别名、媒体上传接口、私有网络限制 | 提供对应文档或最小脱敏请求示例；不提供真实密钥 |
| 实际计费规则 | 输入/输出单价、视觉计费、缓存等，特别是第三方转发服务 | 实现者按实际服务核实；未核清不报精确成本承诺 |
| 已有可用媒体传输方式 | 有序图片编码/上传等 | 默认优先适配LLaVA多帧方式；不要求你把私有原片改成公网链接 |

预算耗尽是run级停止条件：保存检查点，尚未处理的对象保持pending，不把它们伪装成质量reject。模块4已经提交审核但接口异常/无法获得合法结论的对象按当前v1进入reject，并以技术原因单列统计。

## 2. 你可以指定，也可以交给我拟默认配置的项目

这些会影响数据分布。首轮可以回复“按建议小试”，但正式扩量前需要在配置中冻结实际值；下表示例不代表已采纳的生产比例。

| 配置项 | 填写方式 | 建议处理/默认原则 |
|---|---|---|
| 原视频来源名 | 单一来源名称；多来源时给目录或文件到来源的映射 | 本地自建库可用`own_mp4`；已知公开数据集必须保留真实来源，不填Academic2M/LV116K来代表借鉴方法 |
| 原始ID映射 | 有现成来源ID则给映射文件/命名规则 | 没有时程序分配稳定ID；不要求你逐条编ID |
| 数据集展示名 | 如`OwnVideo-General`、`OwnVideo-Long` | 采用项目暂名即可；不影响来源字段 |
| 问题/答案语言 | 中文、英文或混合及配比 | 前文一直使用中文，可先用`zh`小试；字幕/视频来源语言不自动决定问答语言 |
| General/Long启用范围 | 两分支都启用，或首轮先跑哪一支 | 保留两分支；同一长视频可以同时产生局部General与跨段Long |
| General/Long目标混合比例 | 明确按“最终通过条数”还是“训练token”配比 | 初试先观察可产出与通过分布，不强行凑固定比例；扩量前再定 |
| OE/MCQ比例 | 如填写`OE:MCQ=__:__` | 不填可按任务可答性小试，再根据实际供给定配额；不把演示题量当默认 |
| MCQ的3/4/6选项比例 | 填`3选1:4选1:6选1=__:__:__`；这是MCQ内部比例 | 4选1为主、3/6少量已定；确切数字可由我提议后写入试跑配方，不影响单选约束 |
| 每视频候选题上限 | 分General/Long，指定最大候选数或按内容自适应 | 设上限、按证据生成，不设必须凑满的下限；先给小试配额，不承诺最终保留数 |
| 目标总量 | 最大候选数/通过目标数/最大视频数 | 通过目标是目标而非保证；达到预算/输入上限即停止，不为数量放松审核 |
| 任务范围与偏好 | 使用既定任务全集，或排除某些领域/能力 | 已有任务体系默认沿用；场景/动作/OCR/计数等按视频可答性选择 |
| Long入选条件 | 可提供业务定义或最短时长；跨段任务还需多段事实 | 不凭一个通用时长常数定案，先看媒体清单，再拟可执行路由规则；时长条件不替代跨段证据条件 |
| 最长视频/输入体量 | 是否跳过超长文件，有无单文件成本限制 | 按API/内存/预算确定；不能截掉后半片却宣称完成全片任务 |
| 数据划分需求 | 仅构造训练集，还是训练/验证/测试；若分则给比例 | 未指定时不擅自宣称已经有独立评测集；若划分必须按同源/近重复组隔离 |
| 首轮特别关心的问题 | 比如动作细节、计数、长时依赖、小字OCR | 用于挑代表性视频与记录失败组，不新增未经约定题型 |

若你没有这些偏好，不要求一次回答全部；我可以先依据清单与预算制定小试配置。凡未给定且影响收费/处理范围的参数，在实际运行前配置冻结，不无限制运行。

## 3. 工程参数：需要配置，但不需要你逐项决定

这类参数由实现者依据接口文档、媒体探测与小试制定并记录。你若已有机器/接口约束可提供，否则不必查资料填写。

| 模块 | 参数组 | 配置原则与责任 |
|---|---|---|
| 运行环境 | OS、可用CPU/内存、磁盘空间、依赖、网络可达性 | 在明确运行位置后只读探测；GPU并非远程API路线的先决条件，不要求额外部署本地大模型 |
| 输入发现 | 扩展名、排序、清单范围、大小写、符号链接处理 | 受控范围，稳定顺序；原片只读 |
| 媒体检查 | 探测/解码范围、模糊/黑帧/冻结阈值、最小可用尺寸 | 小样本校准并记录，避免不加区分淘汰静态有用内容 |
| 去重 | 精确哈希范围、采样帧感知哈希、文本近重复阈值 | 本地执行，无embedding/语义分类API；相似组与精确重复分开记 |
| Caption采样 | 时间采样、帧尺寸/像素上限、帧组大小、累计汇总触发 | 先保留LLaVA约1FPS、10帧局部/30帧累计的结构作适配基线；不是已证实最优值。用真实PTS并保留真实视图 |
| Caption持久化 | complete/partial/failed、原始响应、稳定媒体ID、缓存键 | L2短片可为空；partial不冒充三级完成；失败隔离 |
| 出题 | 提示版本、输出schema、上下文组织、任务采样、候选数/长度上限 | A3与A5共用API按分支提示；不引入A4视觉补标 |
| 生成解码 | 各角色temperature/top_p/输出上限、超时 | 文本出题与审核可分别配置；仅设置实际API支持参数，不编造通用最优值 |
| API调度 | 并发、RPM/TPM节流、费用/请求停止边界 | 受预算与真实限制控制，不把大并发写死；支出统计覆盖所有角色 |
| 技术重试 | 上游限流/网络错误次数与退避 | 上游可有限技术重试；A7显式关闭客户端/SDK自动重试以满足最多一次请求，失败reject，不因内容失败重写或再审 |
| A7审核视图 | 全局覆盖、题目相关帧/片段、像素/上下文上限 | 审核前按冻结规则准备，长视频不能只送局部正例；不足直接reject，不追加补看 |
| A7判定 | 分项supported/contradicted/insufficient/not_applicable与总体pass/reject | 必需项全通过+本地检查通过才发布；未知/缺项阻断，不能仅凭总状态pass |
| 质量分 | 0–100排序分的定义和校准 | 当前可null，不需要你提供“正确率分数”；不以分数覆盖硬失败 |
| 确定性文本清洗 | HTML实体、残留、空白、模板标签保护 | 送审前做规定的格式标准化；不借清洗修改事实/答案 |
| 输出与状态 | run/version、外部索引、no-clobber staging、发布清单、样本reject目录 | 代码/数据分离，正式版本不覆盖；失效/错误可追溯 |
| 统计 | 输入/候选/通过/reject漏斗、失败类型、分布、费用与耗时 | 质量拒绝与技术失败分开，预算未处理项不算reject |

本版不增加“质量不通过后的修复次数”“A4模型”“第二教师救回”等配置；它们不属于当前授权流程。

## 6. 不需要你逐条提供的东西

- 10个视频各自的时长、分辨率、帧率、采样帧数：由程序探测/记录。

- 三级caption提示词、质量judge提示词、schema、断点恢复逻辑：属于实现交付内容。
- 所有API角色分别购买的模型：一个API可承担当前角色。
- 明文API key、服务器密码或私钥：通过运行环境配置凭据即可。
- 视频到GLM视觉token的手工换算：由实际processor实测或有依据估算。
