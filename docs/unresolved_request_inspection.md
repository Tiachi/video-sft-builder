# 未决模型请求的只读检查

## 提示的含义

`Inference may have executed; refusing automatic retry`表示发送请求后遇到异常，程序不能确定执行/计费状态，因此保留费用预留并禁止自动重发。它不能证明模型已扣费，也不能单独区分HTTP服务错误、连接中断或超时。

当前传输层可能把底层错误包装为PipelineError或UnknownExecution，而请求账本只保留异常类名。若HTTP状态/错误体未保存，诊断工具不能从类名反推出原始错误。界面的unit_id属于管道本地单元，不是供应商HTTP request-id。

## 检查脚本

[inspect_run_failure.py](../scripts/inspect_run_failure.py)只读取一个显式指定的schema2构建：

- 显示角色/状态数量、未决请求、本地异常类名、费用预留、该角色超时和媒体/上下文限制、原片元数据及C_GATE记录。
- 对照构建保存的代码/资产指纹，报告当前运行资产是否匹配；不初始化Store或修改指纹。
- 如有执行pending事件，显示从请求预留至该事件的近似耗时，含请求准备/上传，不是精确模型推理时长。
- 不读取私有Key配置，不打印请求/响应正文、媒体路径、完整URL或URL凭据/查询；不联网、不解码媒体、不扫描数据根目录。
- SQLite只读事务；不改费用、不重发、不恢复模型请求，不创建报告文件。

I/O上限：JSON/单条记录2MiB，SQLite主文件256MiB；默认显示20条未决请求，可显式设1—100，省略数量单独显示；最多100条gate记录、每组256个代码/资产条目。超过范围明确失败。

## 执行

等待推理进程结束；若仍在工作台，输入`/quit`回到普通终端。切到实际项目代码目录，运行：

```bash
bash scripts/git/sync_pull_ff_only.sh
python3 scripts/inspect_run_failure.py --build /absolute/path/to/existing_build
```

将路径替换为现有构建目录，不新建轮次。诊断脚本本身不调用模型，不修改构建。该次交付只增加scripts/tests/docs，不改变运行模块或prompt，因此不因这份工具本身使已有构建指纹失配；其他版本更新仍需检查实际指纹。

如果状态显示unknown_execution，不删除构建、不清空requests、不手改状态、不自动重发。按实际模型/请求时段核对供应商执行和计费日志，再选择明确的恢复动作。不要发送Key、Token、完整私有配置或原始请求正文。

## 验证边界

6项合成测试通过：读取前后数据库/冻结配置/私有文件字节和文件集合不变；运行指纹不变；未决状态保留；省略量明确；敏感payload/Key/URL凭据不输出；缺失DB不创建；资产漂移只报告；不安全资产路径拒绝；CLI正常完成。

这只证明工具的读取和脱敏行为。具体服务错误、是否执行或扣费、网络根因与恢复结果，需要现场证据；工具不保证能恢复早先未保存的异常细节。
