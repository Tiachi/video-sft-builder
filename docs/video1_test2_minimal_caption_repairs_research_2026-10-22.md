- **全套离线验证：** 设计合同检查 PASS；158 项 unittest 中 156 项通过、2 项跳过，124.142 秒。检查未调用教师 API。
- **未执行：** 新的真实模型请求、服务器部署、付费复跑、人审或训练效果验证。
- **保留：** video1_test2 原有拒绝及产物，不改写旧结果，不以确认一项误判为由放行整条 caption。

这不是用一个视频估计整批错误率；该视频已反复用于调试，未来也不能把它当作独立验证集。

## 4. 最小修复包：改哪里、为何这样改

### P1. 将历史不确定性真正送到下一轮

原输入：

~~~python
previous_l2 = summaries[-1]["description"] if summaries else None
~~~

现输入：

~~~python
previous_l2 = deepcopy(summaries[-1]) if summaries else None
~~~

在 A1、A2 的 context 各修改一处，仍使用同一个字段名。历史记录带 description、uncertain_details、id、时间范围和 request_id；A2 的当前 new_l1 原本就带完整记录，不另加一份重复列表。

**决策依据：** E3 是实际传输缺口，修复主要来自代码证据，而不是声称某篇论文规定了此 JSON。补齐来源信息是消除该缺口所需的最小修改。

**选择边界：** 只保证已有警告及来源进入下一轮输入，不保证模型必然保留每条警告。输出仍由模型生成；原始记录继续保存。没有把全部历史 uncertain_details 永久并入新输出，因为某些细节已从摘要中删除或已在当前块被实际确认，永久累积会造成失真和膨胀。

**可推翻条件：** 新请求的 previous_l2 缺少早期警告、来源或时间范围，说明传输修复失败；若输入已齐但模型仍把未解决的旧说法写成确定事实，则需重新评估输出约束，不能把传输测试 PASS 当成质量闭环。

状态：**已实现、合成输入传递验证通过；真实模型输出保持率未验证。**

### P2. L1 优先描述可见事件，减少不必要的逐字字幕

更新 [caption.txt](../prompts/runtime/caption.txt)：

1. 禁止把断续字幕跨帧拼成引号句，禁止凭语言预期补齐或推断语音。
2. 主描述优先实体、动作、状态变化、环境及转场。
3. 短标牌/标签只有清晰可读且确实用于解释场景时才写；不清晰则省略具体字词并记警告。
4. 标题/字幕出现某个地名，不能单独证明镜头拍摄地点；文字表达的动机不能直接写成人物真实意图。

**依据与边界：** E1 直接表明应控制无必要转录；Vript 的表 4 提供了区分内容维度的参考，但其输入还含标题/语音转录，本文不采用那些信息。当前不生产细节 OCR task，因此适度收紧转录符合本版目标；不把所有视觉文字一律屏蔽。

**替代：** 增加 OCR/ASR、逐字核验或专门模型会扩大管道、模态和成本，暂不采用。

**可推翻条件：** 新输出仍出现未经支持的拼句，或为了省去字幕而连明确动作、状态变化也不再描述。应检查这些具体错误，而不是只看 caption 变短或门禁通过率变高。

状态：**prompt 已实现；真实错误率变化未知。**

### P3. L2 在现有调用中核对当前块并保留阶段

同一份 caption prompt 增加 A2 职责：

- 先用当前 30 秒块核对本块 L1 的关键实体/动作/状态/顺序；不能只把段落拼接。
- 纠正或省略当前视觉证据不支持的新增说法；不再向累计摘要复制无关长字幕。
- 累计摘要按视频顺序保留不同阶段和重要变化，压缩重复表达，不能只留开头并省掉中间阶段。
- 保留仍被摘要引用的未解决警告；只有当前块确实提供确认时才清除相应当前块警告。后半段不能替前半段作视觉认证。

**依据：** E2/E4，以及 Video ReCap 的层级组织与附录 S2.1 标注指引；这里迁移的是组织和校核要求，不能继承其专门训练模型的效果。

**重要限制：** 本项目没有新增事实账本、逐事件结构或独立核对调用。是否按顺序覆盖关键阶段仍主要由生成行为和既有门禁决定；只有 start=0/end=duration 或文本不同于 L1 拼接，并不能证明质量达标。

**替代：** 单独事件账本、更严格 claim-ID 消歧、再生成一遍 L3 可增强追踪，但属于后续升级，不作为此次默认修复。

**可推翻条件：** 新 L2 仍复制明显错误，或关键阶段在更新中消失；即使历史警告传递测试通过，也不能认为摘要问题已解决。

状态：**prompt 已实现；摘要事实与阶段覆盖的真实效果未验证。**

### P4. C_GATE 拆分事实，区分反证与证据不足

更新 [caption_gate.txt](../prompts/runtime/caption_gate.txt)，继续在原有一次调用中完成：

| 状态 | 需要什么证据 | 不能怎样判断 | 对整片的影响 |
|---|---|---|---|
| supported | 当前视图有支持该事实的可见证据，并引用帧 ID | 不能用流畅性或上游重复代替视觉证据 | 所有关键事实均为此状态且清单完整时才允许 pass |
| contradicted | 同一实体/事件/相关时段的可见证据明确不相容 | 不能因为其他帧没有出现该事件就断言不存在 | reject |
| insufficient | 无法支持也无法反驳，如漏采、字词不清、身份或顺序不明 | 不改成 invented/partially_supported 等新标签 | uncertain/reject，仍不生成 QA |

**原子化要求：** 不把多个字幕片段、不同镜头、一个正确动作和一个错误属性放到同一 claim 里；也不能为了通过而把原句改成更宽泛的正确说法。保留有问题的实际关键细节供判断。

**依据：** FaithScore 提供拆分事实的机制；Visual Entailment 明确定义充分支持、充分反证和证据不足。将其用于稀疏视频时，加上实体/时段一致约束是本项目的工程推导。

**程序小改：** [quality.py](../src/video_sft_builder/quality.py) 对 decision、claim 文本、status、frame_ids 类型及存在性作检查。supported/contradicted 必须引用现有帧；insufficient 可用空帧列表表示相关时刻未采到。任何 insufficient/contradicted 即使外层写 pass 也不能通过；非法标签保持拒绝，原始响应照存。

**边界：** 程序只能验证结构和引用，无法根据一段理由字符串证明“这张图确实构成反证”。原子事实是否完整、语义判定是否正确仍依赖模型，不能用单元测试宣称语义正确。

**可推翻条件：** 把缺帧当反证、把不足证据变成通过，或靠删减关键 claim 提高通过率。前两者分别需要真实语义核验与结构回归检查；最后一项不能只看通过率发现。

状态：**prompt 和程序均已实现；结构/拒绝规则已局部验证；真实判定质量未验证。**

## 5. 这次修改解决不了的根本限制

固定 32 张稀疏帧不可能保证看到所有短字幕和快速镜头。补充 prompt 不能恢复没有进入输入的像素。

因此，**把误写的 contradicted 改成 insufficient，修正的是归因，仍会拒绝本片**。本轮不能靠“没看见就默认相信上游”来提高产出。即使减少非必要转录，仍有可能因为某个真实、重要的短事件没被门禁采到而拒绝；这是当前成本/保守性合同的结果。

如果上述局部修复后，失败仍主要来自必要事件漏采，而非过度转录或错误归因，后续才值得讨论在同一次 C_GATE 内调整固定帧预算的分配。它可能只是代码小改，但涉及采样策略变更，也可能改变通过率和证据偏差；本次没有自动采用。

## 6. 为什么暂不选其他方案

| 备选 | 潜在收益 | 暂不采用的原因 |
|---|---|---|
| 增加 C_GATE 帧数或改成高 FPS 全视频 | 部分减少短事件漏采 | 提高视觉输入量；仍不能保证精确文字或全事件覆盖 |
| 对 reject 再看一次、再修 caption | 可能挽回一部分数据 | 与拒绝不回流的当前合同不符；增加付费调用 |
| 完整 Self-PEP / 分解后逐事实调用 | 可能改善部分幻觉检测 | 多轮调用放大成本；论文结果不保证每类/每模型均受益 |
| 增加 OCR/ASR/grounding 专家 | 提供专门证据 | 超出首版视觉 caption 支持的任务范围 |
| 更换教师或微调防幻觉模型 | 可能提高模型能力 | 改动大，当前局部软件缺口未先排除 |
| 自动合并所有历史警告 | 可避免表面上的警告丢失 | 不区分已删除/已确认细节，容易累积无效告警 |
| 仅降低 temperature | 可能影响输出稳定性 | 不修复信息传递、取样缺口或事实判断；当前配置本来已较低，不能凭此保证事实正确 |

VideoHallucer 的 Self-PEP 表格本身包含不同任务/模型的涨跌，因此只用它支持“检查具体事实值得研究”，不移植一个统一收益数字。

## 7. 成本、兼容性与运行方式

### 7.1 成本

- 无新增角色、模型、依赖或 API 轮次；L3 仍复用最终 L2。
- 不改变 L1/L2/A7 的 2 FPS、C_GATE 固定帧数、切片范围、候选槽位和原视频审核方式。
- 增加 system prompt 文本、历史 L2 的警告/来源字段，故**文本 token 成本会受影响，不能称总费用完全不变**。实际增量以新请求 usage 为准，不假设字符数等于供应商 token。
- 固定 prompt 的实测 UTF-8 长度：caption 从 1,114 增至 3,116 字节，每次增加 2,002 字节；C_GATE 从 831 增至 3,024 字节，每次增加 2,193 字节。标准 60 秒的 8 次 caption+1 次门禁共增加 18,209 字节固定提示文本；标准 1 小时的 480 次 caption+1 次门禁约增加 963,153 字节。它们都不是实际 token 数或人民币费用，也未包含历史记录字段、实际输出长度变化和网络封装。
- 如果新 caption 通过门禁并进入 QA，A3/A5/A7 将按原链路收费；这不是多了一轮审核，但总费用不能再与此前 QA=0 的 9 次调用直接相比。
- 本次离线研究、改代码及测试没有调用教师模型；付费推理新增 0 次。

### 7.2 数据格式和历史轮次

最终 12 顶层字段、两分支任务及 192 模板不变。caption 输出仍只有 description 与 uncertain_details；改变的是内部 previous_l2 请求字段从字符串到完整对象，已同步修改运行 prompt。

代码/prompt 进入运行指纹，**旧轮次不能在新指纹下直接继续或重解释缓存响应**。video1_test2 已完成且拒绝，本次不对它执行 /resume、重审或改判。提示词已变更，旧 caption-only 恢复机制也不能用来绕过 exact-match 保护。

未来验证需要新的明确命名轮次；本次没有创建。服务器同步应等已有运行结束，不更新运行中的源码。GitHub 维护备份；本文不声称服务器已部署。

这里“9 次”为本地合成请求记录，不是 9 次网络请求。测试不判断模型是否读懂视频、是否按提示拆分了真实事实。

设计合同检查 PASS；完整 unittest 158 项中 156 项通过、2 项跳过，耗时 124.142 秒，涵盖旧静默截断、预算、恢复、两分支调度与导出回归。最初在受限 Windows 沙箱中有临时目录写入和 Git Bash 进程权限错误，随后以正常进程权限复测通过；没有修改测试以绕过这些失败。

完整输出留在仓库外的私有诊断日志中，不提交 Public；其中中转/Git 测试使用合成载荷及替身，并非真实上传或模型调用。两项真实 FFmpeg 集成测试因当前测试进程未找到 FFmpeg/ffprobe 而跳过，不能据此宣称 Linux 媒体处理已重新验收。

### 8.2 后续小规模真实检验方案（提出，未执行）

以旧配置产物为基线，不重新花费一次基线请求。新配置先仅跑 caption 阶段，避免尚未观察 caption 效果就直接消耗 A3/A5/A7 费用。video1_test2 原片可作为已知故障回归；还需要不同风格的未反复调试视频才能评估迁移。

观察项：

1. L1 是否仍把文字片段拼成不成立的长句；明确动作/状态是否保留。
2. L2 是否纠正本块错误、保留必要旧阶段，还是仅改变措辞或机械拼接。
3. 保留的不确定事实是否继续携带警告；警告消失是否因为对应细节被删除或有本块视觉确认。
4. C_GATE 的反证引用是否真的与同一事实、实体和时间范围冲突；漏采是否改为 insufficient。
5. caption 长度、警告数量、三态分布、调用次数、usage、费用及拒绝原因。**不把通过率增加单独作为成功。**

明确不安排批量人审，不据自动标签估计真实错误率；如果后续检查仍只由同一模型自判，语义效果应继续标 unknown。已反复调试的单视频只能是回归证据。

停止/升级条件：

- 传输、枚举或调用预算回归失败：停止进入真实试跑，先修程序。
- 在保留必要视觉信息的前提下，已知错句或错误反证减少：说明值得继续小规模核验，不等于可扩大生产。
- 若主要剩余问题是稀疏视图缺失必要证据：重新讨论采样信息量；不能通过放松 insufficient 放行规则解决。
- 若完整输入下仍反复丢警告/阶段：再评估一个小型显式事实/阶段结构；本次未先引入。
